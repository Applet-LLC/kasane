11. ヘルパー動作とアプリ別レイヤー

トレイの kasane が、キーボードの外の動作を、キーで動かします。

  • ヘルパー動作: プログラムの起動、URL やファイルを開く、文字列の入力（日本語も可）、キー入力の列、マウス操作、レイヤーの操作、一時停止の切り替え
  • アプリ別レイヤー: 前面のアプリに合わせて、レイヤーを有効にする、またはそのキーボードのリマップを OFF にする（ゲームなど）

どちらも、トレイが動いている必要があります。設定の保存に管理者権限は要りません。設定ダイアログの OK で保存すると、トレイが数秒で読み直します。

ヘルパー動作の使い方は 2 通り

方法 内容 キーボードへの適用
動作を HLP(Id) でキーに割り当てる キーを押すと、キー自体は何も出さず、トレイが動作を実行する 要る
トリガーを作る F13〜F24 などのキー（と修飾キーの組み合わせ）を、トレイが監視して実行する 要らない

トレイが止まっているときは、HLP(Id) のキーは何も出しません。トリガーのキーは、普通のキーとして通ります。

例: キーでメモ帳を起動する

  1. エディタで、メモ帳を起動させたいキーをクリックします。
  2. 開いた画面の左の一覧から ヘルパー動作 を選び、新しい動作... を押します。
  3. 種類を プログラムを起動する にして、パスに notepad.exe を入れ、名前を付けて OK を押します。キーに HLP(1) のようなコードが入ります。
  4. キーの割り当ての画面も OK で閉じ、キーボードに適用(ON) を押します。
  5. そのキーを押すと、何も入力されずに、メモ帳が起動します。

エディタの画面下の ヘルパー... を押すと、設定ダイアログが、「ヘルパー動作」タブを開いた状態で開きます。

「ヘルパー動作」タブ

動作とトリガーを、一覧で管理します。対象は このキーボード と 全キーボード共通 から選びます。

範囲 保存先 使う場面
このキーボード 設定フォルダの <UniqId>\helper.json そのキーボードだけで動かす
全キーボード共通 設定フォルダの tray.json どのキーボードでも動かす

動作を探すときは、キーボードごとの設定が先、共通の設定が後です。動作の Id は 0〜65535 で、このキーボードの分と共通の分で重ならない数にします。

動作の一覧の下の 上へ、下へ で、一覧の並びを変えられます。Id は変わらないので、HLP(Id) の割り当てはそのままです。

動作を 削除 するときは、その HLP(Id) を使っているキーの割り当てとキー置換が、確認の画面に並びます。使っている場所の割り当ても外す（既定でオン）のままにすると、設定ダイアログの OK で、キーの割り当ては ▽（透過）に戻り、置き換え先がその動作のキー置換は無効になります（9. マクロ・コンボ・タップダンス・キー置換の「削除・複製・並べ替え」と同じ）。

  • 調べるのは、今開いているキーボードだけです。全キーボード共通 の動作を消すときは、ほかのキーボードの割り当ては確認できません。
  • もう一方の範囲に同じ Id の動作があるときは、HLP(Id) のキーはそちらを実行し続けるので、割り当ては外しません。

動作の種類

種類 内容
プログラムを起動する プログラムを起動する。notepad.exe のように PATH にあるものは、名前だけでもよい。%USERPROFILE% のような環境変数が使える。管理者への昇格はしない
URL・ファイル・フォルダを開く URL、ファイル、フォルダを、関連付けられたアプリで開く
キー・文字列・マウスの操作 キー、文字列、待ち、マウス、ホイール、IME の ON/OFF の手順を、順に実行する
文字列を入力する 設定した文字列を、そのまま入力する。いま入力できる場所の、現在の位置に追記される。改行は Enter、タブは Tab として送る。日本語や記号も、そのまま送る。バックスラッシュなどに特別な意味はない。最大 900 文字。入力の間だけ IME を OFF にすることもできる
アプリ管理レイヤーの操作 対象は、そのキーを押したキーボード。IME 連動や、前面のアプリの規則と合わせて、OR で効く。アプリ管理レイヤーを、有効にする、無効にする、切り替える、押している間だけ有効にする
一時停止・再開 トレイの一時停止と再開を切り替える
行末まで切り取る Emacs の C-k。行末までを切り取り、続けて押した分をクリップボードにつなぐ

手順（Sequence）の書き方

手順は、1 行に 1 つずつ書きます。# で始まる行は無視されます。text の中の \\ はバックスラッシュです（日本語のフォントでは ¥ の形で表示され、¥ キーで入力できます）。ime は、今の状態を見て、違うときだけ変えます。

key LCTL(KC_C)       キーを押して離す
down KC_A            キーを押す
up KC_A              キーを離す
vk IME_ON            仮想キーを押して離す（IME_ON、IME_OFF、0x16、LSHIFT+F1 など）
text こんにちは\n     文字列を打つ（\n は Enter、\t は Tab）
delay 50             待つ（ミリ秒、0〜10000）
mouse left           ボタンをクリック（left、right、middle、x1、x2）
move 10 -5           マウスを今の位置から動かす
moveto 100 200       マウスを画面の座標へ動かす
wheel -120           縦ホイール（120 で 1 ノッチ）
hwheel 120           横ホイール
ime off              IME を OFF にする（on、off、toggle）
ime off abort        失敗したら、この動作の残りをやめる

欄の上のボタンで、行を挿入できます（カーソルのある行の次に入ります）。

ボタン 内容
キーを押して挿入 命令（key、down、up）を選び、このボタンを押してから入れたいキーを押す。Esc で取消。Win キーや Alt+Tab は取れない
選んで挿入... キーボード図や一覧から、キーを選ぶ
マウス操作を挿入 ▾ ボタンのクリック、押す、離す、移動、ホイールの定型の行を選ぶ。数値は、挿入後に書き換える
IME 操作を挿入 ▾ IME を ON にする、OFF にする、切り替える行を選ぶ。方式を固定した行も選べる
仮想キーを挿入 ▾ IME ON、IME OFF、半角/全角、変換、無変換など、日本語 IME 向けの仮想キーの行を選ぶ

手順は最大 2000 件です。待ちは、1 回で 10 秒まで、1 つの動作の合計で 60 秒までです。マウスのボタンを押している間だけ押す（ドラッグ）には、手順に mouse left down、離したときの手順に mouse left up を書きます。

IME の ON/OFF

日本語の IME が ON のとき、key で送るキーは、かな入力や変換の対象になります。意図した文字を出したい手順の前に、ime off を書いてください。IME の今の状態を読み、すでに OFF なら何もしません。ON のときだけ OFF にします。

どうやって切り替えるかは、設定ダイアログの IME 連動 タブの IME の切り替え方 で選びます。

選択 切り替え方
自動（既定） ふだんのトレイは、IMM32 で変える。変えられなければ、IME オン / IME オフのキーを送る。トレイが管理者として動いているときは、Alt+半角/全角を先に送る
IME オン / オフ キー ON にするときは IME オン、OFF にするときは IME オフのキーを送る。日本語キーボードの配列で使える。OS の設定は要らない
変換 / 無変換 ON にするときは変換、OFF にするときは無変換を送る。Windows の設定の Microsoft IME の「キーとタッチのカスタマイズ」で、変換に IME-オン、無変換に IME-オフを割り当てておく
Alt+半角/全角で切り替え Alt+半角/全角を送る。押すたびに ON と OFF が入れ替わるキーなので、今の状態を読めないアプリでは送らない
IMM32 キーを送らずに、IMM32 で変える

IME オン / オフ キーと、変換 / 無変換は、ON か OFF かを直接指定するキーです。今の状態を読めないアプリにも送れます。キーを送っても IME が変わらなかったときは、IMM32 で変えます。

変換 / 無変換は、Microsoft IME に割り当てないまま選ぶと、変換が再変換として働きます。入力済みの文字が変換の対象になり、文字が変換中の状態に変わることがあります。無変換で IME が OFF にならなかったときは、割り当てが無いとみなし、変換 / 無変換を送らなくなります（ログに 1 行残ります）。割り当てたあとは、IME の切り替え方 をいったんほかのものにして OK を押し、もう一度 変換 / 無変換 にして OK を押すか、トレイを起動し直してください。ただし、最初に ime on を実行したときは、まだ見分けられません。

トレイが管理者として動いているときは、キーをドライバ経由で送ります。管理者として動くウィンドウにも届きます。ふだんのトレイは、Windows の SendInput で送ります。

今の状態をどう読むかは、同じタブの IME の状態の取得方法 に従います（IME 連動とNICOLA）。

切り替えに失敗したときは、ログ（tray.log）に理由を残し、手順を続けます。ime off abort のように abort を付けると、その動作の残りをやめます。切り替えたときも、どの方法で変えたかがログに 1 行残ります。

文字列を入力する では、入力の間だけ IME を OFF にする にチェックを付けると（終わったら元に戻します）、同じことができます。失敗したときに入力しないかも選べます。Text は文字を Unicode のまま送るので、ふだんは IME の状態に左右されません。崩れるアプリがあるときに使ってください。

IME が切り替わらないとき

アプリによっては、ime で IME を切り替えられません。そのときは、IME の切り替え方 をほかのものに変えるか、ime の代わりに vk IME_ON / vk IME_OFF を試してください。仮想キーを挿入 ▾ から挿入できます（次の節）。

以前の版で書いた、方式を指定した行（ime off imm、ime on key、ime off altkanji、ime on tsf）は、そのまま動きます。書いた方式だけを使い、失敗しても別の方式には切り替えません。新しく書くときは、方式を書かずに ime off とだけ書いてください。

仮想キー（vk）で送る

IME ON と IME OFF のキー（Microsoft の日本語キーボード向けの VK_IME_ON、VK_IME_OFF）は、key では送れません。スキャンコードを持たないキーだからです。vk で送ります。

vk IME_ON            IME を ON にするキー
vk IME_OFF           IME を OFF にするキー
vk KANJI             半角/全角（切り替えのキー）
vk LSHIFT+F1         修飾キーは + でつなぐ

vk は、ime と違って IME の今の状態を読みません。キーを送るだけです。名前は VK_ を付けても付けなくてもかまいません。文字キー（A〜Z）、テンキー（NUMPAD4、ADD など）、F1〜F24、矢印や編集のキー（LEFT、HOME、DELETE など）、音量・メディアのキー（VOLUME_UP など）も名前で書けます。数字キー（0〜9）は vk VK_4 のように VK_ を付けて書きます（VK_ を付けない 4 は数値として読みます）。そのほかのキーも数値（vk 0x70）で書けます。押す、離すを分けるときは、vkdown、vkup を使います。

制限事項

IME の ON/OFF は、効かないことがあります。IME とアプリの組み合わせによります。

  • アプリによっては、IME を切り替えられません。 IME のウィンドウを持たないアプリや、応答しないアプリには、IMM32 の操作が届きません。切り替えに失敗すると、ログ（tray.log）に理由が残ります。IMM32 でだめなときは IME キーでもう一度試しますが、それでも変わらなければ、上の vk を試してください。
  • 管理者として動いているウィンドウでは、key、vk、文字列の一部が届かないことがあります。 届くかどうかは、キーの種類と並びによって変わります。通常のウィンドウでは、すべて届きます。IME の ON/OFF そのものは、ふだんのトレイでも IMM32 で切り替えられます。トレイが管理者として動いているときは、手順の先頭の ime off でドライバ経由のキーが送られると、後ろの key も届きました（2026-11-02 の試験。Alt+半角/全角で確かめた）。IME がもともと OFF で何も送らなかったときや、IME の切り替え方 が IMM32 のときは、この効果はありません。
  • Text の「元に戻す」は、アプリによっては確かめられません。 IME の状態を読み取れないアプリでは、入力のあとに IME を元の状態へ戻せたかどうかを確認できません。
  • Microsoft IME で確かめています。Google 日本語入力など、ほかの IME は確かめていません。

どの場合も、IME の切り替えに失敗しても、手順や文字列そのものは続けて実行されます（abort を付けたときは、その動作の残りをやめます）。

例: トリガーで、Ctrl+F1 から文字列を出す

「修飾キー＋キー」で、決めた手順を出します。適用は要りません。

  1. エディタの画面下の 設定... を開き、ヘルパー動作 タブの トリガー の 追加... を押します。
  2. 必要なら 名前 を付けます（一覧と、割り当ての一覧に出ます）。キーに KC_F1、修飾キーに Ctrl を指定します。
  3. 種類を キー・文字列・マウスの操作 にして、手順に出したい内容を書きます（例: text こんにちは）。OK を押します。
  4. Ctrl+F1 を押すと、手順が実行されます。Ctrl+F1 自体は、アプリに届きません。

実行の間は、押している Ctrl が OS から隠されます。出力に Ctrl が掛からず、Ctrl+A のような別のショートカットになりません。実行が終わったとき、Ctrl をまだ押していれば、押した状態に戻されます。

手順の中で Ctrl を使いたいときは、手順に key LCTL(KC_C) のように書きます。押している修飾キーを隠さずに送りたいときは、トリガーの編集画面の 実行中も、押している修飾キーを送る にチェックを付けます。

トリガーとキーの割り当て

トリガーは、キーの割り当てではなく、トレイが、キーボードフックで見ているキーです。トリガーに KC_F13 を結び付けたら、F13 を出すキーを、キーボードに用意します。F13 の物理キーがなければ、別のキーに KC_F13 を割り当てます（キーの割り当て画面の 基本 などで選べます）。

エディタのキーボード図では、次の印で見分けられます。

  • H: キーの割り当てが HLP(Id) のキー。動作の名前と内容が、マウスを載せると出ます。
  • T: そのキーが出すキーに、トリガーがあるキー。トリガーの名前と内容が出ます。

トリガーの注意

  • トリガーが 1 つでもあると、トレイがキーボードフックを使います。一致したキーは、アプリに届かなくなります。F13〜F24 など、普段使わないキーが向いています。
  • 修飾キーは、押している分と過不足なく一致したときだけ一致します。左右は区別しません。
  • Alt や Win を使うと、単独で離したときに、メニューやスタートが開くことがあります。操作の手順で修飾キーを隠したり戻したりするときは、間に F24 の入力を入れて防ぎます。それ以外の動作では、Shift と Ctrl の組み合わせがおすすめです。
  • Win を含むトリガーで F16 を選ぶと、環境によっては、スライドしてシャットダウンの画面が出ることがあります。Win を使うときは、F13〜F15 や F17〜F24 など、別のキーを選んでください。
  • トリガーの修飾キーに Alt または Win を含む手順は、実行の前と後に、F24 を 1 回ずつ押して離す入力をアプリに送ります。F24 にショートカットを割り当てているアプリやツールがあると、それが動いてしまいます。Ctrl と Shift だけのトリガーでは、F24 は使いません。使いたくないときは、トリガーに Alt と Win を含めないか、実行中も、押している修飾キーを送る にチェックを付けます。

一時停止と再開をキーで行う

トレイのメニューの 一時停止 と同じ動作を、キー 1 つで行えます。

  1. 設定... の ヘルパー動作 タブで、種類を「一時停止・再開」にして動作を作ります。
  2. トリガーに、F13 などのキーを結び付けます。

トリガーは、一時停止中も動くので、同じキーで再開できます。HLP(Id) でキーに割り当てた場合は、一時停止中にキーボードのリマップが止まるので、同じキーでは再開できません。

一時停止中は、一時停止の切り替えだけが動きます。

行末まで切り取る（Emacs の C-k）

種類を「行末まで切り取る」にすると、Emacs の C-k と同じ動きをするキーを作れます。設定する項目はありません。

  1. 設定... の ヘルパー動作 タブで、種類を「行末まで切り取る」にして動作を作ります。
  2. キー置換 の置き換え先に、その動作の HLP(Id) を書きます。例えば Ctrl+K の置き換え先を HLP(Id) にします。
  3. キーボードに適用(ON) を押します。

動きは次のとおりです。

  • Shift+End、Ctrl+X を送って、行末まで切り取ります。切り取った文字列は、クリップボードに入ります。
  • Ctrl+K を続けて押すと、切り取った文字列が 1 つにつながります。Ctrl+Y（貼り付け）で、まとめて戻せます。
  • 行末で押したときは、改行をつないで Delete を送ります。次の行が上がってきます。
  • 切り取りで改行まで取れるアプリ（ブラウザのテキスト欄など）では、改行をつなぎに入れず、Enter と ← を送って元に戻します。
  • つなぐのをやめるのは、Ctrl+K 以外のキーを押したとき、前面のウィンドウが変わったとき、クリップボードに別の内容が入ったとき、60 秒たったときです。
  • 押している Ctrl は、動作の間だけアプリに隠します。隠さないと、Shift+End が Ctrl+Shift+End になり、文書の終わりまで選ばれてしまいます。

使うときの注意です。

  • トレイが動いている必要があります。止まっていると、そのキーは何も出しません。
  • 最初に使ったときから、トレイは、実際のキー入力を見張ります。Ctrl+K 以外のキーが押されたかを知るためで、キーの内容は記録しません。
  • メモ帳などの一般的なアプリで確かめています。選択がないと行全体を切り取る VS Code のようなアプリでは、動きが合いません。アプリごとに動きを変える対応は、これからです。

Emacs 風の設定例に、この動作を入れる方法は、samples\emacs\EMACS-KEYBINDINGS.md（インストール先）の「Ctrl+K を Emacs と同じ動きにする」にあります。

アプリ別レイヤー

前面のアプリに応じて、アプリ管理レイヤーを自動で有効にします。または、そのキーボードのリマップを OFFにします（ゲームなど）。設定ダイアログの アプリ別レイヤー タブで設定します。

例: 特定のアプリでだけレイヤーを変える

  1. 設定... の アプリ別レイヤー タブを開きます。
  2. 対象（このキーボード、または全キーボード共通）を選び、追加... を押します。
  3. 実行中のアプリから選ぶ... で、対象のアプリのウィンドウを選びます。exe の名前が入ります。
  4. 有効にするレイヤー（0〜15）にチェックを付けます。ゲームなどでリマップを止めたいときは、リマップをOFFにする にチェックを付けます。OK を押します。
  5. 設定ダイアログも OK で閉じると、保存されます。そのアプリが前面のときだけ、レイヤーが立ちます。

規則は、上から順に見て、最初に一致したものを使います。このキーボード の規則は、全キーボード共通 の規則より先に見ます。上へ、下へ で順番を変えられます。どれにも一致しないときは、「既定」の規則を使います。

条件 内容
exe exe のファイル名（code.exe）。\ を含むときは、フルパスで比べる
パス、タイトル exe のフルパス、ウィンドウのタイトルの正規表現（大文字小文字を区別しない部分一致）
クラス ウィンドウのクラス名（完全一致）
のどかと同じ照合 のどかの window と同じ文字列（exe のフルパス:クラス:…:フォーカスのクラス、または exe のフルパス:タイトル:…）に対する正規表現。のどかの条件は、どちらかが一致すればよい にチェックを付けると、クラスとタイトルのどちらかが一致すれば一致する（付けないと両方）

既定の規則 にチェックを付けた規則は、どの規則にも一致しなかったときに使われます。指定した条件は、すべて一致したときに一致します。空の項目は見ません。条件を 1 つも指定していない規則は、使われません。有効にしたレイヤーは、IME 連動など、ほかのレイヤーとは別に重なります。

トレイが落ちても、リマップを OFF にしたキーボードは、次の起動で ON に戻ります。一時停止中は、この OFF の切り替えは行われません。

動く条件と制約

  • 管理者として動くウィンドウが前面のとき: ログオン時に自動起動する kasane-tray.exe は、UI アクセスの権限で動くので、キー入力も、送る入力も届きます。次の場合は届きません。
    • UI アクセスのない版（kasane-tray-nua.exe）や、開発用のビルドを使っている場合
    • UAC の確認画面などの、セキュアデスクトップが前面の場合
    • トレイを、エクスプローラー（ログオン時の自動起動、スタートメニュー、ダブルクリック）以外のプログラム（コマンドプロンプトなど）から起動した場合。エラーは出ませんが、UI アクセスなしで動きます。エクスプローラーから起動するか、ログオンし直してください。管理者保護を使っているときは、インストーラーが作るタスクで起動しても、UI アクセスが付きます。
  • 署名が信頼されないか、Program Files の外に置かれたトレイは、エクスプローラーから起動したときに、失敗して何も出ません。署名済みのインストーラーで入れたときは起こりません。その場合は、同じフォルダの kasane-tray-nua.exe を起動してください。
  • ロック画面、ユーザーの切り替え、別のセッションがアクティブなときは、動作を実行しません。
  • マウスの相対移動（move）は、Windows のポインター加速を受けます。位置を決めたいときは moveto を使います。
  • 5 秒より前の HLP(Id) の押下は捨てられます。トレイが止まっていた間のキーが、あとでまとめて動かないようにするためです。

動かないとき

  1. トレイが動いているかを、通知領域のアイコンで確かめます。
  2. HLP(Id) の Id に対応する動作があるかを確かめます。キーの割り当て画面が、注意を出します。
  3. HLP(Id) のキーは、キーボードに適用(ON) を押したかを確かめます。
  4. 設定フォルダの tray.log に、読み込みの失敗が出ていないかを確かめます。
