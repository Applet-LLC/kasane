# 11. ヘルパー動作とアプリ別レイヤー

トレイの kasane が、キーボードの外の動作を、キーで動かします。

- ヘルパー動作: プログラムの起動、URL やファイルを開く、文字列の入力（日本語も可）、キー入力の列、マウス操作、レイヤーの操作、一時停止の切り替え
- アプリ別レイヤー: 前面のアプリに合わせて、レイヤーを立てる、またはそのキーボードのリマップを OFF にする（ゲームなど）

どちらも、トレイが動いている必要があります。設定の保存に管理者権限は要りません。設定ダイアログの **OK** で保存すると、トレイが数秒で読み直します。

## ヘルパー動作の使い方は 2 通り

| 方法 | 内容 | キーボードへの適用 |
|---|---|---|
| 動作を `HLP(Id)` でキーに割り当てる | キーを押すと、キー自体は何も出さず、トレイが動作を実行する | 要る |
| トリガーを作る | F13〜F24 などのキー（と修飾キーの組み合わせ）を、トレイが監視して実行する | 要らない |

トレイが止まっているときは、`HLP(Id)` のキーは何も出しません。トリガーのキーは、普通のキーとして通ります。

## 例: キーでメモ帳を起動する

1. エディタで、メモ帳を起動させたいキーをクリックします。
2. 開いた画面の左の一覧から **ヘルパー動作** を選び、**新しい動作...** を押します。
3. 種類を **プログラムを起動する (Launch)** にして、パスに `notepad.exe` を入れ、名前を付けて **OK** を押します。キーに `HLP(1)` のようなコードが入ります。
4. キーの割り当ての画面も **OK** で閉じ、**キーボードに適用(ON)** を押します。
5. そのキーを押すと、何も入力されずに、メモ帳が起動します。

![ヘルパー動作の割り当て](../img/ja/helper-assign.png)

エディタの画面下の **ヘルパー...** を押すと、設定ダイアログが、「ヘルパー動作」タブを開いた状態で開きます。

## 「ヘルパー動作」タブ

動作とトリガーを、一覧で管理します。対象は **このキーボード** と **全キーボード共通** から選びます。

![ヘルパー動作のタブ](../img/ja/helper-tab.png)

| 範囲 | 保存先 | 使う場面 |
|---|---|---|
| このキーボード | 設定フォルダの `<UniqId>\helper.json` | そのキーボードだけで動かす |
| 全キーボード共通 | 設定フォルダの `tray.json` | どのキーボードでも動かす |

動作を探すときは、キーボードごとの設定が先、共通の設定が後です。

### 動作の種類

| 種類 | 内容 |
|---|---|
| プログラムを起動する (Launch) | プログラムを起動する。管理者への昇格はしない |
| URL・ファイルを開く (Open) | URL、ファイル、フォルダを、関連付けられたアプリで開く |
| 操作の手順 (Sequence) | キー、文字列、待ち、マウス、ホイール、IME の ON/OFF の手順を、順に実行する |
| 文字列を入力する (Text) | 設定した文字列を、そのまま入力する。いま入力できる場所の、現在の位置に追記される。改行は Enter、タブは Tab として送る。最大 900 文字。入力の間だけ IME を OFF にすることもできる |
| アプリ管理レイヤーの操作 (AppLayer) | アプリ管理レイヤーを、入れる、切る、切り替える、押している間だけ入れる |
| 一時停止・再開 (PauseToggle) | トレイの一時停止と再開を切り替える |

### 手順（Sequence）の書き方

手順は、1 行に 1 つずつ書きます。`#` で始まる行は無視されます。

```
key LCTL(KC_C)       キーを押して離す
down KC_A            キーを押す
up KC_A              キーを離す
vk IME_ON            仮想キーを押して離す（IME_ON、IME_OFF、0x16、LSHIFT+F1 など）
text こんにちは\n     文字列を打つ（\n は Enter、\t は Tab）
delay 50             待つ（ミリ秒、0〜10000）
mouse left           ボタンをクリック（left、right、middle、x1、x2）
move 10 -5           マウスを今の位置から動かす
moveto 100 200       マウスを画面の座標へ動かす
wheel -120           縦ホイール（120 で 1 ノッチ）
hwheel 120           横ホイール
ime off              IME を OFF にする（on、off、toggle）
ime on tsf           方式を固定する（imm、tsf、key、altkanji）
ime off key abort    失敗したら、この動作の残りをやめる
```

![操作の手順の編集](../img/ja/helper-sequence.png)

欄の上のボタンで、行を挿入できます（カーソルのある行の次に入ります）。

| ボタン | 内容 |
|---|---|
| **キーを押して挿入** | 命令（`key`、`down`、`up`）を選び、このボタンを押してから入れたいキーを押す。Esc で取消。Win キーや Alt+Tab は取れない |
| **選んで挿入...** | 画面のキーボードや一覧から、キーを選ぶ |
| **マウス操作を挿入 ▾** | ボタンのクリック、押す、離す、移動、ホイールの定型の行を選ぶ。数値は、挿入後に書き換える |
| **IME 操作を挿入 ▾** | IME を ON にする、OFF にする、切り替える行を選ぶ。方式を固定した行も選べる |
| **仮想キーを挿入 ▾** | IME ON、IME OFF、半角/全角、変換、無変換など、日本語 IME 向けの仮想キーの行を選ぶ |

手順は最大 2000 件です。待ちは、1 回で 10 秒まで、1 つの動作の合計で 60 秒までです。マウスのボタンを押している間だけ押す（ドラッグ）には、手順に `mouse left down`、離したときの手順に `mouse left up` を書きます。

### IME の ON/OFF

日本語の IME が ON のとき、`key` で送るキーは、かな入力や変換の対象になります。意図した文字を出したい手順の前に、`ime off` を書いてください。IME の今の状態を読み、すでに OFF なら何もしません。ON のときだけ OFF にします。

方式は、行の最後に書いて選びます。

| 書き方 | 動作 |
|---|---|
| 書かない（自動） | IMM32 で変える。変えられなければ、IME キーを送る |
| `imm` | IMM32 だけを使う。IME のウィンドウに ON/OFF を設定する |
| `key` | IME キー（IME ON、IME OFF）だけを送る。状態を読めなくても送る |
| `altkanji` | Alt+半角/全角だけを送る。切り替えのキーなので、今の状態を読めないときは送らない |
| `tsf` | TSF だけを使う（実験的）。効くかどうかは、IME とアプリによる |

方式を書いた行は固定です。失敗しても、ほかの方式には切り替えません。失敗したときは、ログに残して手順を続けます。`abort` を付けると、その動作の残りをやめます。

文字列を入力する (Text) では、**入力の間だけ IME を OFF にして、終わったら元に戻す** にチェックを付けると、同じことができます。方式と、失敗したときに入力しないかも選べます。Text は文字を Unicode のまま送るので、ふだんは IME の状態に左右されません。崩れるアプリがあるときに使ってください。

#### 仮想キー（vk）で送る

IME ON と IME OFF のキー（Microsoft の日本語キーボード向けの `VK_IME_ON`、`VK_IME_OFF`）は、`key` では送れません。スキャンコードを持たないキーだからです。`vk` で送ります。

```
vk IME_ON            IME を ON にするキー
vk IME_OFF           IME を OFF にするキー
vk KANJI             半角/全角（切り替えのキー）
vk LSHIFT+F1         修飾キーは + でつなぐ
```

`vk` は、`ime` と違って IME の今の状態を読みません。キーを送るだけです。名前は `VK_` を付けても付けなくてもかまいません。数値（`vk 0x70`）でも書けます。押す、離すを分けるときは、`vkdown`、`vkup` を使います。

#### 制限事項

IME の ON/OFF は、効かないことがあります。IME とアプリの組み合わせによります。

- **アプリによっては、IME を切り替えられません。** IME のウィンドウを持たないアプリや、応答しないアプリには、IMM32 の操作が届きません。切り替えに失敗すると、ログ（`tray.log`）に理由が残ります。方式を固定していなければ、IME キーを送る方式に切り替えて、もう一度試します。
- **`tsf` は、ほとんど効きません。** 実験的な方式です。試験では、テスト用のウィンドウで効かず、効いたように見えたアプリでも、確かではありませんでした。ふだんは使わず、自動か `imm`、`key`、`altkanji` を選んでください。
- **新しく開いたウィンドウでは、最初の 1 文字が入らないことがあります。** IME の操作とは関係なく、kasane を通さずにキーを送っても同じことが起きました。ウィンドウ側の性質と考えられます。`delay` を入れても直りませんでした。2 文字目以降は入ります。
- **管理者として動いているウィンドウでは、`key`、`vk`、文字列が届かないことがあります。** どのキーが届くかは、キーの種類と並びによって変わります。`delay` を入れても、ダミーのキーを先頭に置いても直りませんでした。IME は `ime`（自動か `imm`）で切り替えられます。通常のウィンドウでは、並びに関係なくすべて届きます。
- **Text の「元に戻す」は、アプリによっては確かめられません。** IME の状態を読み取れないアプリでは、入力のあとに IME を元の状態へ戻せたかどうかを確認できません。
- Microsoft IME で確かめています。Google 日本語入力など、ほかの IME は確かめていません。

どの場合も、手順や文字列そのものは、方式を書いた行が失敗しても続けて実行されます（`abort` を付けたときは、その動作の残りをやめます）。

## 例: トリガーで、Ctrl+F1 から文字列を出す

「修飾キー＋キー」で、決めた手順を出します。適用は要りません。

1. エディタの画面下の **設定...** を開き、**ヘルパー動作** タブの **トリガー** の **追加...** を押します。
2. キーに `KC_F1`、修飾キーに **Ctrl** を指定します。
3. 種類を **操作の手順 (Sequence)** にして、手順に出したい内容を書きます（例: `text こんにちは`）。**OK** を押します。
4. Ctrl+F1 を押すと、手順が実行されます。Ctrl+F1 自体は、アプリに届きません。

![トリガーの編集](../img/ja/helper-trigger.png)

実行の間は、押している Ctrl が OS から隠されます。出力に Ctrl が掛からず、Ctrl+A のような別のショートカットになりません。実行が終わったとき、Ctrl をまだ押していれば、押した状態に戻されます。

手順の中で Ctrl を使いたいときは、手順に `key LCTL(KC_C)` のように書きます。押している修飾キーを隠さずに送りたいときは、トリガーの編集画面の **実行中も、押している修飾キー（Ctrl など）を送る** にチェックを付けます。

### トリガーの注意

- トリガーが 1 つでもあると、トレイがキーボードフックを使います。一致したキーは、アプリに届かなくなります。
- 修飾キーは、押している分と過不足なく一致したときだけ一致します。左右は区別しません。
- Alt や Win を使うと、単独で離したときに、メニューやスタートが開くことがあります。操作の手順で修飾キーを隠したり戻したりするときは、間に F24 の入力を入れて防ぎます。それ以外の動作では、Shift と Ctrl の組み合わせがおすすめです。
- Win を含むトリガーで F16 を選ぶと、環境によっては、スライドしてシャットダウンの画面が出ることがあります。Win を使うときは、F13〜F15 や F17〜F24 など、別のキーを選んでください。
- トリガーの修飾キーに Alt または Win を含む手順は、実行の前と後に、F24 を 1 回ずつ押して離す入力をアプリに送ります。F24 にショートカットを割り当てているアプリやツールがあると、それが動いてしまいます。Ctrl と Shift だけのトリガーでは、F24 は使いません。使いたくないときは、トリガーに Alt と Win を含めないか、**実行中も、押している修飾キー（Ctrl など）を送る** にチェックを付けます。

## 一時停止と再開をキーで行う

トレイのメニューの **一時停止** と同じ動作を、キー 1 つで行えます。

1. **設定...** の **ヘルパー動作** タブで、種類を「一時停止・再開 (PauseToggle)」にして動作を作ります。
2. トリガーに、F13 などのキーを結び付けます。

トリガーは、一時停止中も動くので、同じキーで再開できます。`HLP(Id)` でキーに割り当てた場合は、一時停止中にキーボードのリマップが止まるので、同じキーでは再開できません。

一時停止中は、一時停止の切り替えだけが動きます。

## アプリ別レイヤー

前面のアプリに応じて、アプリ管理レイヤーを自動で立てます。または、そのキーボードのリマップを OFF（素通し）にします（ゲームなど）。設定ダイアログの **アプリ別レイヤー** タブで設定します。

![アプリ別レイヤーのタブ](../img/ja/apprules-tab.png)

### 例: 特定のアプリでだけレイヤーを変える

1. **設定...** の **アプリ別レイヤー** タブを開きます。
2. 対象（このキーボード、または全キーボード共通）を選び、**追加...** を押します。
3. **実行中のアプリから選ぶ...** で、対象のアプリのウィンドウを選びます。exe の名前が入ります。
4. 立てるレイヤー（0〜15）にチェックを付けます。ゲームなどでリマップを止めたいときは、**リマップをOFFにする** にチェックを付けます。**OK** を押します。
5. 設定ダイアログも **OK** で閉じると、保存されます。そのアプリが前面のときだけ、レイヤーが立ちます。

![前面のアプリの規則](../img/ja/apprules-editor.png)

![実行中のアプリから選ぶ](../img/ja/apprules-picker.png)

規則は、上から順に見て、最初に一致したものを使います。**上へ**、**下へ** で順番を変えられます。どれにも一致しないときは、「既定」の規則を使います。

| 条件 | 内容 |
|---|---|
| exe | exe のファイル名（`code.exe`）。`\` を含むときは、フルパスで比べる |
| パス、タイトル | exe のフルパス、ウィンドウのタイトルの正規表現（部分一致） |
| クラス | ウィンドウのクラス名 |
| のどかと同じ照合 | のどかの `window` と同じ文字列で照合する |

指定した条件は、すべて一致したときに一致します。条件を 1 つも指定していない規則は、使われません。立てたレイヤーは、IME 連動など、ほかのレイヤーとは別に重なります。

トレイが落ちても、リマップを OFF にしたキーボードは、次の起動で ON に戻ります。一時停止中は、この OFF の切り替えは行われません。

## 動く条件と制約

- 管理者として動くウィンドウが前面のとき: ログオン時に自動起動する `kasane-tray.exe` は、UI アクセスの権限で動くので、キー入力も、送る入力も届きます。次の場合は届きません。
  - UI アクセスのない版（`kasane-tray-nua.exe`）や、開発用のビルドを使っている場合
  - UAC の確認画面などの、セキュアデスクトップが前面の場合
  - トレイを、エクスプローラー（ログオン時の自動起動、スタートメニュー、ダブルクリック）以外のプログラム（コマンドプロンプトなど）から起動した場合。エラーは出ませんが、UI アクセスなしで動きます。エクスプローラーから起動するか、ログオンし直してください。管理者保護を使っているときは、インストーラーが作るタスクで起動しても、UI アクセスが付きます。
- 署名が信頼されないか、`Program Files` の外に置かれたトレイは、エクスプローラーから起動したときに、失敗して何も出ません。署名済みのインストーラーで入れたときは起こりません。その場合は、同じフォルダの `kasane-tray-nua.exe` を起動してください。
- ロック画面、ユーザーの切り替え、別のセッションがアクティブなときは、動作を実行しません。
- マウスの相対移動（`move`）は、Windows のポインター加速を受けます。位置を決めたいときは `moveto` を使います。
- 5 秒より前の `HLP(Id)` の押下は捨てられます。トレイが止まっていた間のキーが、あとでまとめて動かないようにするためです。

## 動かないとき

1. トレイが動いているかを、通知領域のアイコンで確かめます。
2. `HLP(Id)` の `Id` に対応する動作があるかを確かめます。キーの割り当て画面が、注意を出します。
3. `HLP(Id)` のキーは、**キーボードに適用(ON)** を押したかを確かめます。
4. 設定フォルダの `tray.log` に、読み込みの失敗が出ていないかを確かめます。
