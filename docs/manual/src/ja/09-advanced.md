# 9. マクロ・コンボ・タップダンス・キー置換

エディタの画面下の **マクロ...**、**コンボ...**、**タップダンス...**、**キー置換...** で、複雑な動作を作ります。この 4 つの動作は、ドライバが処理するので、トレイが動いていなくても効きます。

| 機能 | 内容 |
|---|---|
| マクロ | キーの列を順に打つ。最大 128 個（0〜127）。1 つのマクロは 64 ステップまで |
| コンボ | 2 つのキーの同時押しで、別のキーを出す。最大 16 個 |
| タップダンス | タップの回数や長押しで、動作を変える。最大 16 個（0〜15） |
| キー置換 | 修飾キーとキーの組み合わせを、別のキーや動作に置き換える。最大 128 個（0〜127） |

設定ダイアログの「機能」タブで、使わない機能を OFF にできます（[13. 設定ダイアログ](13-settings.html)）。OFF にしても、定義の中身は消えません。

キーボード図のキーから始めることもできます。キーの割り当ての画面の **コンボ**、**キー置換**、**マクロ / タップダンス** か、キーの右クリックのメニューで、そのキーに関わる定義を開いたり、そのキーを入れた定義を作ったりできます（[8. キーの割り当て](08-key-assign.html#combo-keyoverride)）。

<a id="editors-common"></a>
## 編集画面の共通の操作

4 つの編集画面は、すべて同時に開いたまま使えます。画面は少しずつずらして開きます。同じ画面をもう一度開こうとすると、開いている画面が前に出ます。

画面の下のボタンは、左から次のとおりです。

| ボタン | 内容 |
|---|---|
| **適用** | 画面を閉じずに、プロジェクトへ反映する |
| **OK** | 反映して閉じる |
| **キャンセル** | 反映せずに閉じる。Esc も同じ |

**適用** も **OK** も押さずに閉じると、その画面の編集内容は捨てられます。変更をキーボードに送るには、そのあとエディタで **キーボードに適用(ON)** を押します。

左の一覧には、`番号: 名前 — 中身` の形で定義が並びます。右側の先頭の **名前（任意）** 欄に、わかりやすい名前を付けられます。名前は、画面の表示とエクスポートのファイルだけに使われ、動作には関係しません。中身が空の番号にも、名前だけ付けておけます。名前だけの番号は未使用のままで、中身を入れるまで、キーボードには適用されません。

キーコードの欄の右の **×** を押すと、その欄が空になります。

<a id="list-ops"></a>
### 削除・複製・並べ替え

一覧の下のボタンで、右側に出している番号を操作します。どれも、**適用** か **OK** を押すまで、プロジェクトには入りません。

| ボタン | 内容 |
|---|---|
| **削除** | 中身と名前を消して、未使用に戻す。確認の画面が出る |
| **複製** | 中身と名前を、空いている番号に写す。名前には「(複製)」が付く |
| **上へ**、**下へ** | 1 つ前・後の番号と入れ替える。コンボとキー置換だけ |

- マクロとタップダンスは、キーに `MACRO(n)`、`TAPDANCE(n)` と番号で割り当てるので、番号を動かせません。削除しても、後ろの番号は詰めません。並べ替えのボタンも出ません。
- コンボとキー置換は、ほかから番号で使われないので、削除すると後ろの番号が 1 つずつ前に詰まります。キー置換は、番号の小さいものから順に照合するので、並べ替えで優先する順を変えられます。
- 複製したコンボは、元と同じキーを使うので、無効にしてあります。キーを変えてから、**無効にする** のチェックを外してください。

マクロとタップダンスを削除するとき、その番号を使っている場所があれば、確認の画面に一覧が出ます。調べるのは、キーマップの全レイヤー、コンボの出力、タップダンスの各欄、キー置換の置き換え先です。**使っている場所の割り当ても外す**（既定でオン）のままにすると、次のように外します。

| 使っている場所 | 外し方 |
|---|---|
| キーの割り当て | ▽（透過）に戻す。レイヤー 0 では、刻印のキーとして動く |
| タップダンスの欄 | 空（動作なし）にする。4 つの欄が全部空になったタップダンスは、未使用にする |
| コンボの出力、キー置換の置き換え先 | その定義を無効にする（中身は残す） |

チェックを外すと、使っている場所はそのまま残り、そのキーを押しても何も起きなくなります。ヘルパー動作の削除も、同じ確認の画面を使います（[11. ヘルパー動作とアプリ別レイヤー](11-helper-apprules.html)）。

### 定義を無効にする

書いた内容は残したまま、キーボードには適用したくないときは、右側の **無効にする** にチェックを付けます。一覧の行には `[無効]` と出ます。チェックを外せば、また適用されます。

- **キーボードに適用(ON)** を押すと、無効の定義は、キーボードに送られません。すでにキーボードに入っている定義は、消えます。
- 無効の定義の中身は、検証されません。書きかけのままでも、適用は止まりません。チェックを外したときに、検証されます。
- 中身が空の番号には、チェックを付けられません。
- 無効のマクロやタップダンスを、キーの割り当て（`MACRO(n)`、`TAPDANCE(n)`）やコンボの出力から使っていると、適用のときに「無効にしてあります」と知らせます。そのキーを押しても、何も起きません。
- 無効のコンボのキーは、ほかのコンボに使えます。
- エディタの画面下のボタンは、無効の数も表します（`マクロ(2・無効1)...`）。無効のコンボとキー置換には、キーボード図の **C**・**R** の印が付きません。
- 無効の指定は、設定ファイルとエクスポートのファイルに残ります。ドライバから設定を読み直すと、無効だった定義は戻りません（ドライバには入っていないため）。

<a id="macro"></a>
## マクロ

**マクロ...** で、順に打つキーの列を作ります。作ったマクロは、キーに `MACRO(n)` を割り当てて動かします。

![マクロの編集](../img/ja/macro-editor.png)

- マクロの中身の欄には、キーコードを、スペースで区切って並べます（例: `KC_H KC_I`）。`LCTL(KC_C)` のように、修飾キー付きのキーも書けます（`C(KC_C)` でも同じです。Ctrl+Shift+T は `LCTL(LSFT(KC_T))`）。
- 1 つのマクロは 64 ステップまでです。キー 1 つで 2 ステップ、修飾キー 1 つにつき、さらに 2 ステップを使います。
- **押して入力** は、取り込みを続けます。押したキーが、前のキーの後ろに空白をあけて足されます。Esc か、ボタンをもう一度押すと終わります。
- **選ぶ...** は、**追加** で欄の末尾に足します。画面を開いたまま続けて選べます。**閉じる** で終わります。

### MACRO(n) を入れる

`MACRO(n)` は、番号を打たなくても入れられます。

- `MACRO(n)` を書ける入力欄（コンボの「送るキー」、タップダンスの各タップと長押し、キー置換の置き換え先）の右にある **マクロ...** を押すと、「番号: 名前 — 中身」の一覧が出ます。選ぶと `MACRO(n)` が入ります。
- マクロの画面を開いたままにして、ほかの画面の入れたい入力欄を一度クリックし、マクロの画面の一覧の行をダブルクリックする方法もあります。**他の画面の入力欄に MACRO(n) を入れる** のボタンでも同じです。最後にクリックした入力欄に入ります。
- 入れ忘れないように、次の 2 つの工夫があります。マクロの内容を変えて、まだ入れていないとき（入れ先の入力欄をクリックしてあり、その欄に `MACRO(n)` が入っていないとき）、**他の画面の入力欄に MACRO(n) を入れる** のボタンが、太字と色つきで目立ちます。その状態で **OK** を押すと、「入れてから閉じますか?」と聞かれます。**はい** で入れて閉じ、**いいえ** で入れずに閉じ、**キャンセル** で閉じずに戻ります。タップダンスの画面の `TAPDANCE(n)` も同じです。

<a id="combo"></a>
## コンボ

**コンボ...** で、2 つのキーの同時押しに、別のキーを割り当てます。

![コンボの編集](../img/ja/combo-editor.png)

- **キー-1** と **キー-2** は、一覧から選びます。同時押しの対象は、2 つのキーだけです。
- 1 つのキーは、1 つのコンボにしか使えません。無効にしたコンボのキーは、ほかのコンボに使えます。
- コンボは物理のキーに対して働くので、どのレイヤーでも同じように効きます。
- **送るキー** には、普通のキーのほか、`LCTL(KC_Z)` のような修飾キー付きのキー（押している間）や、`MACRO(n)`（成立したときに 1 回）も指定できます。
- コンボの対象のキーには、キーボード図で C の印が付きます。
- 同時押しと見なす時間（ComboTerm）は、設定ダイアログの「タイミング」タブで変えられます。

<a id="tapdance"></a>
## タップダンス

**タップダンス...** で、**1回タップ**、**長押し**、**2回タップ**、**3回タップ** に、それぞれ別の動作を割り当てます。各欄の右に、**押して入力**、**選ぶ...**、**マクロ...** のボタンがあります。作ったタップダンスは、キーに `TAPDANCE(n)` を割り当てて動かします。

![タップダンスの編集](../img/ja/tapdance-editor.png)

- 1 回、2 回、3 回のタップには、普通のキーのほか、`LCTL(KC_C)` のような修飾キー付きのキーや、`MACRO(n)` も指定できます。
- 長押しには、`MT(MOD_LCTL,KC_NO)` のような修飾キー、`LT(1,KC_NO)` のようなレイヤーのほか、修飾キー付きのキー（押している間）、`LM(1,MOD_LCTL)`、`MACRO(n)`（長押しが決まったときに 1 回）も指定できます。`MT`・`LT` のタップ側のキーは使われません。
- 空欄（または `KC_NO`）にした欄は「動作なし」です。そのタップ回数や長押しでは、何も起きません。4 つの欄を全部空にすると、その番号は未使用になります。
- タップの間隔と長押しの判定の時間（TapDanceTerm）は、設定ダイアログの「タイミング」タブで変えられます。
- タップダンスの画面でも、一覧の行のダブルクリック（または **キーの割り当て画面の入力欄に TAPDANCE(n) を入れる** のボタン）で、キー割り当ての画面のキーコード欄に `TAPDANCE(n)` が入ります。`TAPDANCE(n)` は、キーに割り当てる動作なので、入れ先は、キー割り当ての画面のキーコード欄だけです。

<a id="key-override"></a>
## キー置換

**キー置換...** で、修飾キーとキーの組み合わせを、別のキーに置き換えます。**修飾キー**、**キー**、**置き換え先** の 3 つを入れます。修飾キーは、`MOD_LCTL|MOD_LSFT` のように複数書けます。欄の右の **Shift**、**Alt**、**Ctrl**、**Win** のチェックでも入れられます（チェックと欄は連動します。チェックを付けると左側の修飾キーが入り、外すと左右とも消えます）。全部が押されているときに置き換わります（左右は区別しません）。

![キー置換の編集](../img/ja/keyoverride-editor.png)

| 例 | 設定 | 結果 |
|---|---|---|
| Shift+BS を Delete にする | 修飾キー `MOD_LSFT`、キー `KC_BSPACE`、置き換え先 `KC_DELETE` | Shift+BS が Delete になる |
| US 配列の刻印のキーボードを、JIS 設定の Windows で使う | 修飾キー `MOD_LSFT`、キー `KC_2`、置き換え先 `KC_LBRC` | Shift+2 が @ になる |

- **キー** は、レイヤーで切り替えたあとに出るキーで比べます。3 つの欄を全部空にすると、その番号は未使用になります。
- 置き換えている間、条件の修飾キーは、一時的に離されます。置き換え先に `LSFT(KC_X)` のように書けば、その修飾キーは掛かります。
- 置き換え先には、`MACRO(n)` も指定できます。キーを押したときに、マクロを 1 回実行します（マクロの機能が ON のときだけ）。**キーを押し続けたときも、マクロを繰り返す** にチェックを付けると、オートリピートのたびに繰り返します。
- 置き換え先には、レイヤー操作（`OSL(n)`、`TG(n)`、`TO(n)`、`DF(n)`）、ヘルパー動作（`HLP(n)`）、マークモード（`MARK(on)`、`MARK(off)`、`MARK(toggle)`）も指定できます。キーは出さず、キーの割り当てに同じ動作を置いたときと同じ処理をします。条件の修飾キーは離しません。例: Ctrl+X を `OSL(1)` にすると、次に押す 1 キーだけが、レイヤー 1 の割り当てになります。
- `MARK(on)` は、Emacs のマークモードに入ります（`MARK(off)` で終わり、`MARK(toggle)` で切り替えます）。入っている間は、移動のキー（←↑→↓、Home、End、PageUp、PageDown）に Shift が付き、移動のたびに選択範囲が広がります。移動のキーと修飾キー以外のキーを押すと、そのキーを送ったあとで終わります。前面のウィンドウが変わったときも終わります（トレイが動いているとき）。例: Ctrl+Space を `MARK(on)` にします。
- `OSL(n)` などで切り替えた先のレイヤーに、`LCTL(KC_S)` のような修飾付きキーを置くと、出力のキー（この例は Ctrl+S）が、別のキー置換に当たることがあります。当たらないようにするには、そのキーに `MACRO(n)` を割り当てます。
- `MO(n)`、`LT(n, kc)`、`KC_NO` などは、置き換え先に使えません。
- 古いドライバ（キー置換が 32 個までのもの）では、33 個目以降と、レイヤー操作・ヘルパー動作の置き換え先は適用されません。

### 例: Ctrl+F1 でマクロを出す

ドライバが処理するので、トレイが動いていなくても効きます。

1. **マクロ...** で、出したい内容のマクロを作ります（例: マクロ 0）。
2. **設定...** の「機能」タブで、マクロとキー置換が ON になっていることを確かめます。
3. **キー置換...** を開き、修飾キーに `MOD_LCTL`、キーに `KC_F1`、置き換え先に `MACRO(0)` を指定して、**OK** を押します。
4. **キーボードに適用(ON)** を押します。
5. Ctrl+F1 を押すと、マクロ 0 が 1 回実行されます。Ctrl+F1 自体は、アプリに届きません。

実行の間だけ、押している Ctrl が OS から離され、終わったときにまだ押していれば、戻されます。マクロの出力に Ctrl が掛からないためです。マクロの中で Ctrl を使いたいときは、マクロの中身に `LCTL(KC_C)` のように書きます。

Alt や Win を条件にしたときは、メニューやスタートが開かないよう、間に Ctrl のタップが入ります。

キーを押し続けたときは、既定ではマクロを繰り返しません。繰り返したいときは、置き換え先が `MACRO(n)` のときに出る **オートリピートも、マクロを繰り返す** にチェックを付けます。

マクロの機能が OFF のときは、この置き換えは働かず、Ctrl+F1 が、そのまま届きます。

> 文字列や待ち、マウス操作を含む手順を、同じように Ctrl+F1 で出したいときは、ヘルパー動作のトリガーを使います（[11. ヘルパー動作とアプリ別レイヤー](11-helper-apprules.html)）。ただし、トレイが動いている必要があります。
