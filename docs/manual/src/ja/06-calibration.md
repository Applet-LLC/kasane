# 6. キャリブレーション

キャリブレーションは、キーボード図の上のキーが、実際のどのキーかを、キーを押して確かめる作業です。

標準的な JIS や US のキーボードでは、キーボード図のどのキーが実際のどのキーかは、レイアウトから自動で決まります。そのため、キャリブレーションは通常は要りません。次のような場合に行います。

- キーボード図に、赤い枠のキー（どのキーか分からないキー）があり、そのキーを変更したい
- 設定したのに、違うキーが入れ替わる

Windows のキーボードレイアウトの指定が必要な場合は、キーボードレイアウト設定ツール「まな」の利用もご検討ください。キートップの刻印とキーボードレイアウトが一致しない場合でも、キーのリマップはできます。ただし、たとえば Shift + 2 を送ったときに、`@` が出るか `"` になるかは、Windows のキーボードレイアウトの設定で決まります。マクロを作るときに問題になるので、ご注意ください。

- キーボードレイアウト設定ツール「まな」: [Applet LLC のページ](https://appletllc.com/2026/10/07/%E3%82%AD%E3%83%BC%E3%83%9C%E3%83%BC%E3%83%89%E3%83%AC%E3%82%A4%E3%82%A2%E3%82%A6%E3%83%88%E8%A8%AD%E5%AE%9A%E3%83%84%E3%83%BC%E3%83%AB-%E3%81%BE%E3%81%AA-1-00/)、[GitHub](https://github.com/Applet-LLC/mana)

物理的なキーボードの配列が、用意してある JP109、US104、10KEY から離れていて、物理的なキーの位置と、取得できたスキャンコードが違う場合は、[KLE から配列を追加する](05-editor-basics.html#kle-import)を見て、キーボードに合った配列にしてください。

## 開く

エディタの画面下の **キャリブレーション...** を押します。

![キャリブレーションの画面](../img/ja/calib-main.png)

画面の上の **モード** で、次の 3 つから選びます。最初は「入力確認」です。

| モード | 管理者権限 | 内容 |
|---|---|---|
| 入力確認 | 要らない（管理者のほうが正確） | キーを押して、キーボード図の対応するキーが光るかを確かめる |
| 個別キー | 必要 | 実測したいキーを選んで、実際に押して測る |
| 全体 | 必要 | 示されたキーを、順番に押して測る |

画面が前面にある間は、押したキーは Windows には送られません（画面には「この画面が前面の間、キーは Windows に届きません」と出ます）。Enter や Win キーを押しても、何も起きません。操作はマウスで行ってください。別のウィンドウをクリックすると一時停止し、キーは普段どおりに戻ります。

<a id="calibration-check"></a>
## 入力確認

キーボードのキーを押すと、キーボード図の対応するキーが橙色になり、離すと戻ります。一度押したキーには ✓ が付きます。


全部のキーを一通り押して、✓ が付かないキーや、押したキーと違うキーが光るキーがあれば、キャリブレーションが必要です。**確認済みをリセット** で、✓ を消せます。

### 管理者のとき

キーを、ドライバから直接受け取ります。リマップで置き換える前の物理キーが見えます。右 Shift や、カタカナひらがな、英数、半角/全角のキーの押下と解放も、確実に届きます。選んでいるキーボードの入力だけを見ます。

![管理者のときの入力確認](../img/ja/calib-main-admin.png)

### 管理者でないとき

画面に「正確に確かめるには、管理者として再起動してください」と出ます。この場合は、Windows のキー入力（低レベルキーフック）で確認するため、次の制限があります。

- 確認できるのは、リマップで置き換えた後のキーです。置き換えている場合は、先に **OFF** を押してください。
- どのキーボードの入力かは区別できません。
- 右 Shift が拡張キー（E0 付き）として見えるため、扱えません。
- 一部のキーで、解放が届かず、押したままに見えることがあります。

![管理者でないときの入力確認](../img/ja/calib-main.png)

<a id="calibration-single"></a>
## 個別キーのキャリブレーション

1. キーボード図の、実測したいキーをクリックします。黄色になります。
2. キーボードの、対応するキーを押します。
3. 続けて、別のキーも実測できます。
4. 終わったら **実測値を保存して閉じる** を押します。

![個別キーのキャリブレーション](../img/ja/calib-single.png)

<a id="calibration-all"></a>
## 全体のキャリブレーション

黄色で示されたキーを、順番に押します。

![全体のキャリブレーション](../img/ja/calib-all.png)

| ボタン | 内容 |
|---|---|
| **1つ戻る** | 直前のキーに戻る |
| **このキーを飛ばす** | そのキーボードにないキーを飛ばす |
| **実測値を保存して閉じる** | 実測した値を保存して閉じる |
| **閉じる** | 実測値を保存せずに閉じる。何も実測していないとき（入力確認だけのとき）に使う |

## 実測した値を消す

実測値を消して、既定のスキャンコードに戻すには、キーボード図の上のキーを右クリックして、**実測値を削除** を選びます。

## 結果の反映

実測した値が標準と違うキーは、キーボード図の上で橙色の枠になります。結果は、**キーボードに適用(ON)** を押したときに反映されます。

> 実測した値は、別の機器には持ち越されません。キーボードを買い替えたときは、やり直してください（[15. バックアップと移行](15-backup-migrate.html)）。

<a id="special-keys"></a>
## Pause、NumLock、Copilot、Office、AltGr のキー

- Pause / Break: 物理キーは、2 つの信号（`E1 1D` と `45`）で届きます。ドライバが、1 つのキーとしてまとめて扱います。Pause を別のキーに置き換えることも、何かのキーを Pause にすることもできます。
- NumLock: スキャンコードは `0x45` で、Pause の 2 つ目の信号と同じ値です。ドライバが見分けるので、ふだんは気にする必要はありません。
- Copilot キー、Office キー: 多くのキーボードでは、1 つのキーではなく、複数のキーの同時押し（Copilot は Win + Shift + F23、Office は Ctrl + Shift + Alt + Win）として届きます。そのため、1 つの割り当てでは変えられません。同時押しのそれぞれのキー（左 Win、左 Shift、F23 など）の割り当てを変えると、同時押し全体が変わります。お使いのキーボードで、どのキーが届くかは、**入力確認** で確かめてください。
- AltGr: AltGr のある配列（ドイツ語など）の Windows では、右 Alt が AltGr として働きます。かさね では変えられません。[16. トラブル対応、既知の制限など](16-reference.html)を見てください。

## 既知の制限

右 Shift を `E0 36` で出すキーボードは、キャリブレーションで扱えない場合があります。実機では確認できていません。
