# kasane の設定ファイルと、バックアップ・移行

kasane の設定が、どこに・何として保存されているか、バックアップや別のPCへの移行で何が要るかをまとめる。
内容はソース（`KeymapProject.cs`・`HelperConfig.cs`・`TrayConfig.cs`・`Portable/*`・`LayoutFolders.cs`・`LayerEngine.c`）から書いた。
実機での確認は第7節にまとめてある（未確認の記述には「未確認」と書く）。

## 1. 設定の置き場所は3つ

| 置き場所 | 何が入るか | 誰が書く |
|---|---|---|
| **ドライバのレジストリ** `HKLM\SYSTEM\CurrentControlSet\Services\kbdlayer\Parameters` | 実際にキー入力に効いている設定の本体 | ドライバ（設定画面の「適用」やKeymapToolの書き込み系IOCTLのとき。管理者権限が要る） |
| **ユーザーごとのファイル**（設定フォルダ） | 設定画面で編集する設定の元データ、トレイの設定、トレイの状態の記録 | 設定画面（kasane.exe）、トレイ（kasane-tray.exe） |
| **ライセンス** `%ProgramData%\kbdlayer-license\…`（DPAPI で保護） | ライセンスのトークン、署名鍵 | ライセンスサービス（kasane-license-svc） |

- **キーを実際にリマップしているのは、ドライバのレジストリの設定**。ユーザーごとのファイル（`project.json`）は、設定画面で編集するための元データで、「キーボードに適用」でドライバに書き込む。
  レジストリに設定が無い場合（再インストール後など）の予備にもなるが、**適用しなくても、レジストリにある設定は動き続ける**。
  設定画面に保存ボタンは無い。`project.json` は、閉じるとき・別のキーボードへ切り替えるとき・適用のときに自動で保存される。保存したが適用していない設定がある状態で閉じると、確認が出る（`docs/TUTORIAL-GUI.md`）。
- ライセンスは、バックアップ・持ち出しの対象外（再インストール後、サービスが保存済みのライセンスキーで再確認する）。

## 2. ユーザーごとのファイル（設定フォルダ）

設定フォルダは、環境変数 `KASANE`（絶対パス。インストーラーで指定できる）があればそこ、無ければ `%LOCALAPPDATA%\applet\kasane`（`HelperConfig.BaseDirectory`）。
以下、このフォルダを `<設定フォルダ>` と書く。`<UniqId>` は8桁の16進数（例 `CDEC0000`。第4節）。

| ファイル | 中身 | バックアップ | 別のPCへの持ち出し |
|---|---|---|---|
| `<設定フォルダ>\<UniqId>\project.json` | キーボード1台分の設定の元データ: レイヤー（スロット順のキーコード）、マクロ、コンボ、タップダンス、キー置換、タイミング（TapTerm など）、機能のON/OFF、NICOLA、レイアウト名（`LayoutName`）、実測したスキャンコード（`MeasuredScanCodes`）、`HardwareId` | 要る | **直接コピーしない**（UniqId が別の機器では別のフォルダになる）。エクスポート／インポートを使う（第5節） |
| `<設定フォルダ>\<UniqId>\helper.json` | そのキーボードのヘルパー動作、トリガー（F13〜F24 など）、アプリ別レイヤーの規則 | 要る | 同上 |
| `<設定フォルダ>\tray.json` | トレイの設定: IME連動のON/OFF、アイコンへのレイヤー番号表示、全キーボード共通のヘルパー設定（共通のトリガー・動作・アプリ別レイヤー） | 要る | コピーしてよい（キーボードに依存しない）。エクスポートの「全体」にも入る |
| `<設定フォルダ>\tray-state.json` | トレイの「一時停止」で止めたキーボードの UniqId の記録 | 不要 | **持ち出さない**（別のPCでは意味が無い） |
| `<設定フォルダ>\tray-mapoff.json` | アプリ別の規則でリマップを OFF にしたキーボードの UniqId の記録 | 不要 | **持ち出さない** |
| `<設定フォルダ>\tray.log` | トレイの異常の記録 | 不要 | 不要 |
| `<設定フォルダ>\kasane-import.json` | インストール時の設定の取り込みで置かれたファイル（設定画面・トレイが、起動時に「まだ設定が無いものだけ」取り込む） | 不要（取り込み後は役目を終える） | — |
| `<設定フォルダ>\backup\before-import-<日時>.kasane.json` | インポートの前に自動で作る、今の設定のバックアップ（実測値・ヘルパー設定を含む。`PortableService.BackupAll`） | 取っておくとよい | エクスポートファイルと同じ形式なので、インポートできる |
| `<設定フォルダ>\Layouts\kle-<名前>.json` | 「KLEから追加」で保存した、利用者のキーボードレイアウト | 要る（これが無いと、そのレイアウトを使う `project.json` が開けない） | コピーしてよい |

注意:
- **利用者のレイアウトの置き場は `<設定フォルダ>\Layouts`**（環境変数 `KASANE` があればその下）。`KASANE` を指定する前に保存したもの（`%LOCALAPPDATA%\applet\kasane\Layouts`）も読み込む（同じ名前は設定フォルダが優先。保存先は設定フォルダ）。同梱の3種（`kle-jp109`・`kle-us104`・`kle-10key`）は、インストール先の `Layouts\` から直接読むので、コピーはされない。
- `project.json` の `LayoutPath` に、同梱以外のレイアウトの**フルパス**が入ることがある。別のPCでは、そのパスが無いので開けない。持ち出すときは、レイアウトファイルも一緒に移す。
- ファイルは UTF-8（BOM なし）の JSON。手で編集できるが、壊れていると読めない（`helper.json` は、壊れたファイルを黙って上書きしない設計。`project.json` の扱いは未確認）。

## 3. ドライバのレジストリ

`HKLM\SYSTEM\CurrentControlSet\Services\kbdlayer\Parameters` の下。

| キー／値 | 中身 |
|---|---|
| `LayerMaps\M_<ModelKey>` | **既定の保存先**。同じ型番のキーボードで共有する設定: レイヤーマップ、マクロ、コンボ、タップダンス、キー置換、各タイミング、機能のON/OFF、NICOLA、`Enabled`（リマップのON/OFF） |
| `LayerMaps\I_<InstanceKey>` | 「この1台だけ」にしたキーボードの設定 |
| `LayerMaps\G_All` | 「すべてのキーボードで共有」にしたときの設定 |
| `LayerMaps\M_<ModelKey>.bak` | インストール時の取り込みで置き換える前の設定（1世代だけ。ドライバは読まない。設定画面の「保存先」タブから戻せる） |
| `DeviceBinding`（値名 = InstanceKey） | そのキーボードの保存先の選択（Model / Instance / Global） |
| `EmergencyRelease` | 緊急解除の組み合わせ（ドライバ全体で1つ） |
| i8042prt の設定 | PS/2（内蔵）キーボードのレイアウトの上書き。`Services\i8042prt\Parameters` と、ドライバ側のプロファイル |

- どの保存先を使うかは「設定の共有範囲」（設定画面の「共有範囲」タブ、`Binding`）で決まる。**共有範囲を変えても、すでに接続中の別のキーボードには、そのキーボードを接続し直すまで反映されない**。
- バックアップは `reg export "HKLM\SYSTEM\CurrentControlSet\Services\kbdlayer\Parameters" kasane-driver.reg`（管理者権限）で取れる。ただし、インストール時のレジストリの構造に依存するので、
  別のPCへ戻すより、エクスポート／インポート（第5節）の方が確実。
- ドライバが見るのは、起動時・キーボードの接続時（`AddDevice`）。

## 4. UniqId・ModelKey・InstanceKey

| 名前 | 何のハッシュか | 性質 |
|---|---|---|
| `InstanceKey` | DeviceInstanceId（`HID\VID_…&PID_…\<接続位置から作られる部分>`） | 1台ごとに違う。**同じキーボードでも、別の USB ポートに挿すと変わる** |
| `ModelKey` | HardwareId の先頭の1件（`HID\VID_…&PID_…&REV_…`） | 同じ型番（同じ改訂番号）で同じ値。ポートを変えても変わらない |
| `UniqId` | **`InstanceKey` と同じ値**（`DeviceId`。キー入力の `ExtraInformation` の上位16bit にも載る） | 設定フォルダの名前 `<UniqId>` になる |

- いずれも16bitのハッシュ（8桁の16進のうち上位4桁だけが意味を持つ）。まれに別のキーボードと一致する。
- 詳しくは `docs/DEVICE-ID.md`。
- 以前のインストーラーは、`UniqId` を `ModelKey` にする「ハードウェアID」モードを選ばせていたが、今は選ばせない（`UniqId` は常に `InstanceKey`）。

つまり、**USB ポートを変えると `UniqId` が変わり、`<設定フォルダ>\<UniqId>\` が別のフォルダになる**。元のポートに戻せば、元の設定がそのまま使える。
ドライバのレジストリの設定は、共有範囲が「同じ型番」（既定）なら、ポートを変えても同じ設定を使う（`ModelKey` は変わらないため）。

## 5. バックアップと移行

### 5.1 基本: エクスポート／インポート

設定画面の「インポート／エクスポート」で、「全体」を選ぶと、すべてのキーボードの設定とトレイの設定を、1つのファイル（`*.kasane.json`）に書き出せる。

入るもの（`PortableFile`）:
- 各キーボード（`Keyboards`）: UniqId、HardwareId、レイアウト名、レイヤー、マクロ、コンボ、タップダンス、キー置換、タイミング、機能のON/OFF、NICOLA、そのキーボードの `helper.json`。
  キーは**スキャンコード**（`SC_XXXX`）で持つので、レイアウト（JIS/US など）に依存しない。
- トレイの設定（`Tray`）: IME連動、全キーボード共通のヘルパー設定。
- 実測値（`MeasuredScanCodes`）は、バックアップのとき（同じ機器へ戻すとき）だけ含める。

入らないもの: `tray-state.json`・`tray-mapoff.json`・`tray.log`、ライセンス、利用者のレイアウトファイル（`Layouts\`）、緊急解除の組み合わせ（ドライバ全体の設定）、i8042prt の設定。

### 5.2 フォルダごとコピーする場合

- 同じPC・同じキーボードへ戻すなら、`<設定フォルダ>` の `<UniqId>\` フォルダ（`project.json`・`helper.json`）、`tray.json`、`Layouts\` をコピーすればよい。`tray-state.json`・`tray-mapoff.json`・`tray.log` は除く。
- 別のPCへは、フォルダの直接コピーより、エクスポート／インポートを使う（`UniqId` が違うため。第5.3節）。

### 5.3 別のPC・別のキーボードへの移行

1. 元のPCで「全体」をエクスポートする。
2. 新しいPCに kasane をインストールし、キーボードを接続する。
3. 設定画面の「インポート」でファイルを読み込む。ファイルのキーボードを、接続中のキーボードに対応づける（`PortableService.AutoMap`）:
   `UniqId` が同じものを先に、次に `HardwareId` が同じものを1台ずつ割り当てる。合わなければ、画面で手で選べる。
4. 配列の違うキーボード（JIS ↔ US、テンキー付きなど）へは、**意図しない割り当てになりうる**（キーマップは物理スキャンコードで決まる）。インポートの報告を確認する。
5. 実測値（`MeasuredScanCodes`）は、別の機器へは持ち越さない（キーボードごとに違うため）。必要ならキャリブレーションし直す。

### 5.4 インストール時に取り込む

インストーラーの「設定ファイルの取り込み」（既定はオフ）で、エクスポートしたファイルを指定すると、インストール時の管理者権限で、ドライバのレジストリ（`LayerMaps\M_<ModelKey>`）へ書く。
Windows 11 の管理者保護で、インストール後に「適用」できない環境のためのもの。環境変数 `KASANE` を指定している場合は、同じファイルが `kasane-import.json` として設定フォルダに置かれ、
設定画面・トレイの設定は、起動時に、まだ設定が無いものだけ取り込まれる。サイレントインストールでは `IMPORT_SETTINGS=1 IMPORT_SETTINGS_FILE=C:\path\x.kasane.json`。
取り込み前の設定は `.bak` に1世代だけ残り、設定画面の「保存先」タブから戻せる。

## 6. 場面ごとの早見表

| 場面 | すること |
|---|---|
| PC を買い替える | 古いPCで「全体」をエクスポート → 新しいPCにインストール → キーボードを接続 → インポート。利用者のレイアウト（`Layouts\`）があれば、一緒にコピー |
| キーボードを買い替える | 古いキーボードの設定を、新しいキーボードへインポート（対応づけを手で選ぶ）。配列が違うときは報告を確認し、キャリブレーションし直す |
| USB ポートを変えた | 設定画面の設定とトレイの設定は引き継がれない。元のポートに戻すか、エクスポート／インポートで移す。ドライバの設定は、共有範囲が「同じ型番」なら引き継がれる |
| 再インストール | ドライバのレジストリ（`Parameters`）は残る（アップグレード時）。アンインストールして再起動した後は消える。事前に「全体」をエクスポートしておく |
| 設定を初期化したい | 設定画面で「OFF（素通しに戻す）」→ 必要なら `<設定フォルダ>\<UniqId>\` を削除、レジストリの `LayerMaps\M_<ModelKey>` を削除（管理者）。トレイの設定は `tray.json` を削除 |
| 管理者保護を有効にしている | 昇格したエディタは別ユーザーで動き、`%LOCALAPPDATA%` が別になる。環境変数 `KASANE` で設定フォルダを固定する（`docs/ADMIN-PROTECTION.md`） |
