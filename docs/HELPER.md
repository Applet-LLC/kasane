# ヘルパー動作とアプリ別レイヤー

タスクトレイの kasane（`kasane-tray.exe`）が、キーで「キーボードの外」の動作を動かします。

- **ヘルパー動作**: キーで、プログラムの起動・URL やファイルを開く・文字列の入力（日本語も可）・キーの列・マウス操作・レイヤーの操作・一時停止の切り替えを行います。
- **アプリ別レイヤー**: 前面のアプリに応じて、レイヤーを立てる、またはそのキーボードのリマップを OFF にします（ゲームなど）。

ヘルパー動作とアプリ別レイヤーの設定は、**管理者権限なしで**保存できます。設定は利用者のフォルダに保存され、設定画面の **OK** で保存すると、トレイが数秒で読み直します。
ただし、キーに `HLP(Id)` を割り当てて動かすには、ほかのキー割り当てと同じく **キーボードに適用**（管理者権限が要ります）が必要です。トリガーとアプリ別レイヤーは適用が要りません。
**トレイが動いている必要があります**（トレイが止まっていると、`HLP(id)` のキーは何も出さず、トリガーのキーは普通のキーとして通ります）。

## すぐ試す

1. メイン画面でキーを選び、**キー割り当て** 画面の **ヘルパー動作** カテゴリを開きます。**新しい動作...** で動作を作ると、そのキーに `HLP(Id)` が入ります。
2. **キーボードに適用** します（`HLP(Id)` はレイヤーマップの一部なので、適用が要ります）。
3. そのキーを押すと、キー自体は何も出さず、トレイが動作を実行します。

F13〜F24 などのキーで動かしたいときは、**設定...** の **ヘルパー動作** タブの **トリガー** に作ります（適用は要りません）。

## 保存先

| 範囲 | 場所 | 使う場面 |
|---|---|---|
| このキーボード | `%LOCALAPPDATA%\applet\kasane\<UniqId>\helper.json` | そのキーボードだけで動かす |
| 全キーボード共通 | `%LOCALAPPDATA%\applet\kasane\tray.json` の `Helper` | どのキーボードでも動かす |

動作を引くときは、キーボードごとの設定 → 共通の設定の順に探します。**helper.json を手で書いてもかまいません**（`samples/helper.sample.json` に例があります）。
構文を間違えると、そのファイルは読まれません（設定画面は、壊れたファイルを黙って上書きせず、理由を出します。トレイは無視して `tray.log` に残します）。

## 動作の種類

動作は `Actions`（`HLP(Id)` から呼ぶ。`Id` は 0〜65535。新しい動作には 1 から振ります）と `Triggers`（キーで動かす）に、同じ形で書きます。

| Type | 内容 | 主な項目 |
|---|---|---|
| `Launch` | プログラムを起動する（昇格はしない） | `Path`、`Args`、`WorkDir`（省略するとトレイの作業フォルダ） |
| `Open` | URL・ファイル・フォルダを、関連付けられたアプリで開く | `Path` |
| `Sequence` | 手順を順に実行する（キー・文字列・待ち・マウス・ホイール） | `Steps`、`ReleaseSteps`（キーを離したとき）、`Repeat`、`KeepMods`（トリガーのみ） |
| `Text` | 設定した文字列を、そのまま入力する（`Apple 漢字` など。いま入力できる場所の現在の位置に追記される。改行は Enter、タブは Tab。`Sequence` の `text` と違い、バックスラッシュに特別な意味は無い。最大 900 文字） | `Text` |
| `AppLayer` | アプリ管理レイヤーを操作する | `Layers`（0〜15）、`LayerOp`（`On` / `Off` / `Toggle` / `Hold`。`Hold` は押している間だけ） |
| `PauseToggle` | トレイの一時停止・再開を切り替える | なし |

`Repeat` が true のときだけ、キーのオートリピートで繰り返し実行します。

`KeepMods` は、**トリガー**（キー＋修飾キー）で動かす `Sequence` と `Text` だけに効きます。既定（false）では、実行の間だけ、トリガーの修飾キーのうち物理的に押している分を OS から隠します（`SendInput` で離したことにし、終わったときにまだ押していれば戻します）。Ctrl+F1 で文字列を出すとき、出力に Ctrl が掛からないようにするためです。true にすると、押している修飾キーを隠さずに実行します。`HLP(id)` のキーには関係しません。

### 一時停止・再開をキーで行う（`PauseToggle`）
トレイのメニューの「一時停止」と同じ動作を、キー 1 つで行えます。機能の追加は要らず、`PauseToggle` の動作を作って、キーに割り当てるだけです。
1. **設定...** の **ヘルパー動作** タブで、動作の種類を「一時停止・再開 (PauseToggle)」にして作ります。
2. キーに結び付けます。次のどちらかです。
   - **`HLP(Id)`**: キー割り当て画面の **ヘルパー動作** から、作った動作をキーに置きます。**キーボードに適用** が要ります。ただし、一時停止中はキーボードのリマップが止まるので、
     `HLP` のキーは届きません（**止めることはできても、同じキーで再開はできません**）。
   - **トリガー（F13〜F24 など）**: **トリガー** に、キー（例: `KC_F13`、修飾キーは `Shift` / `Ctrl` の組み合わせがおすすめ）で結び付けます。トリガーは一時停止中も動くので、
     **同じキーで再開できます**。F13〜F24 の物理キーが無く、別のキーを `KC_F13` に割り当てて出す場合は、一時停止中にそのキーのリマップが止まって F13 を出せないので、
     **同じキーでは再開できません**（物理の F13〜F24 キーを使うか、メニューの「一時停止」で再開してください）。
3. 一時停止中は、`PauseToggle` だけが動きます（ほかの動作は止まります）。

### 手順（Sequence）の書き方

設定画面では、1 行 1 手順のテキストで書きます（`#` から始まる行は無視）。

書くのが大変なものは、欄の上のボタンで挿入できます（カーソルのある行の次に、1 行入ります）:

- **キーを押して挿入**: 命令（`key`／`down`／`up`）を選び、このボタンを押してから入れたいキーを押すと、`key KC_A` のような行が入ります（Esc で取消）。Win キーや Alt+Tab は取れないので、次のボタンを使います。
- **選んで挿入...**: 画面のキーボードや一覧からキーを選びます（`LCTL(KC_C)` のような修飾つきも選べます）。
- **マウス操作を挿入 ▾**: メニューから、ボタンのクリック・押す・離す、移動、ホイールの定型の行を選びます（`mouse left`、`mouse left down`、`move 10 0`、`wheel 120` など。数値は、挿入後に書き換えます）。

```
key LCTL(KC_C)       キーを押して離す（KC_A、LCTL(KC_C)、SC_E06A など）
down KC_A / up KC_A  押す / 離す
text こんにちは\n     文字列を打つ（\n = Enter、\t = Tab、\\ = バックスラッシュ）
delay 50             待つ（ミリ秒、0〜10000）
mouse left           ボタンをクリック（left right middle x1 x2。mouse left down / up も）
move 10 -5           マウスを今の位置から動かす
moveto 100 200       マウスを画面（仮想デスクトップ）の座標へ動かす
wheel -120           縦ホイール（120 で 1 ノッチ）
hwheel 120           横ホイール
```

`helper.json` では、同じ内容を `Steps` の配列（`{ "Key": "LCTL(KC_C)" }`、`{ "DelayMs": 50 }`、`{ "Text": "こんにちは\n" }`、
`{ "Mouse": "Left", "MouseAction": "Down" }`、`{ "MoveX": 10, "MoveY": -5 }`、`{ "Wheel": -120 }` など）で書きます。
手順は最大 2000 件、待ちは 1 回 10 秒・1 動作の合計 60 秒までです。

マウスのボタンを「押している間だけ押す」(ドラッグ) には、`Steps` に `mouse left down`、`ReleaseSteps` に `mouse left up` を書きます。

## トリガー（F13〜F24 などのキー）

`Triggers` は、キー（`Key`）と修飾キー（`Mods`。`MOD_LSFT|MOD_LCTL` のように。左右は区別しません）に動作を結び付けます。

- **1 つでもあると、トレイはキーボードフック（低レベルフック）を張ります。** `HLP(Id)` だけの設定ではフックは張られません。
- 一致したキーは **アプリに届かなくなります**（押下・リピート・解放を飲み込みます）。修飾キーは、押している分と過不足なく一致したときだけです。
- キーボードごとの設定が先、共通が後です。キーボードは、ドライバが入力に刻む識別子（`dwExtraInfo` の上位 16bit）で見分けます。
- F13〜F24 は、キー割り当てで出せます（物理キーが無くても、キーを `KC_F13` に割り当てれば出ます）。
- `Sequence` の修飾キーの扱いは、上の `KeepMods` を見てください（既定では、実行の間だけ隠します）。
- Alt や Win を使うと、単独で離したときにメニューやスタートが開くことがあります。`Sequence` で修飾キーを隠す・戻すときは、間に F24 のキーを入れて防ぎます。それ以外の動作（`Launch` など）では、Shift / Ctrl の組み合わせがおすすめです。
- Win を含むトリガーで **F16** を選ぶと、環境によっては、スライドしてシャットダウンの画面が出ることがあります（トリガーなしで Win+F16 を押しても出るので、Windows 側のホットキーとみられます）。Win を使うときは、F13〜F15・F17〜F24 のように、別のキーを選んでください。
- **F24 を内部で使います。** トリガーの修飾キーに Alt または Win を含む `Sequence` は、実行の前（修飾キーを隠すとき）と後（戻すとき）に、F24 を1回ずつ押して離す入力（`SendInput`、スキャンコード `0x76`）を送ります。F24 にショートカットを割り当てたアプリやツールがあると、それが動いてしまいます。Ctrl・Shift だけのトリガーでは使いません。F24 を使いたいときは、トリガーに Alt・Win を含めないか、`KeepMods` を true にします（修飾キーを隠さないので、F24 も送りません）。トレイのキーフックは、注入された入力を見ないので、この F24 でトリガーが動くことはありません。

## IME連動のレイヤー（`ImeLayers`）

IME の ON/OFF に合わせて、アプリ管理レイヤーを立てる・下ろします。NICOLA（`ImeLink`）とは別の機能で、NICOLA を使わなくても使えます。
設定画面の **IME連動** タブから設定します。

```json
"ImeLayers": { "Enabled": true, "Layers": [1], "Mode": "On" }
```

| 項目 | 内容 |
|---|---|
| `Enabled` | 連動するか（既定は true）。キーボードごとの設定で false にすると、共通の設定があっても、そのキーボードは連動しません |
| `Layers` | 立てるレイヤー（0〜15）。1つ以上 |
| `Mode` | `On`（IME が ON のとき。半角英数のモードも含む。既定）／`Kana`（かな入力のときだけ。IME が ON で、日本語の入力モード） |

- キーボードごとの設定（`helper.json`）が先、無ければ共通（`tray.json` の `Helper`）を使います。
- 立てるレイヤーは、IME 連動（NICOLA）・前面のアプリの規則と同じアプリ管理レイヤーで、キーボード側の `TG` などとは OR で重なります。
- 前面のウィンドウの IME の状態が取れないとき（管理者として動いているウィンドウ、応答しないアプリなど）は、直前の状態を保ちます。
- IME の状態は、IMM32（`WM_IME_CONTROL` の `IMC_GETOPENSTATUS`・`IMC_GETCONVERSIONMODE`）で読みます。Text Services Framework（TSF）は使っていません。
  IMM32 の窓を持たないアプリ（一部のストアアプリなど）では、状態が取れません。
- NICOLA の連動と、同じレイヤーを指していても構いません（どちらかが立てたいときに立てます）。

## アプリ別レイヤー

`AppLayerRules` に規則を並べます。**上から順に見て、最初に一致した規則**を使います。どれにも一致しなければ、`Default` の規則（無ければ何もしません）。
キーボードごとの規則 → 共通の規則の順です。

| 項目 | 内容 |
|---|---|
| `Match.Exe` | exe のファイル名（`code.exe`）。`\` を含めばフルパスで比べる |
| `Match.PathRegex` / `Match.TitleRegex` | exe のフルパス / ウィンドウのタイトルの正規表現（部分一致） |
| `Match.Class` | トップレベルのウィンドウのクラス名 |
| `Match.NodokaClass` / `Match.NodokaTitle` / `Match.NodokaOr` | のどかの `window` と同じ照合（`exeのフルパス:クラス:…:フォーカスのクラス`） |
| `Layers` | 立てるレイヤー（0〜15）。IME 連動など、ほかの入力源のレイヤーとは別に重なります |
| `MapOff` | そのアプリが前面の間、そのキーボードのリマップを OFF（素通し）にする |
| `Default` / `Enabled` / `Name` | どれにも一致しないときの規則 / 有効 / 表示名 |

指定した項目はすべて一致したときに一致します。条件を 1 つも指定していない規則は、照合に使いません。設定画面の **実行中のアプリから選ぶ** で、今開いているウィンドウから
exe とクラスを入れられます。`MapOff` は、一時停止中は触りません。トレイが落ちても、`MapOff` で OFF にしたキーボードは次の起動で ON に戻します。

## 動く条件と制約

- **管理者として動くウィンドウが前面のとき**: インストールしたトレイ（`tray\kasane-tray.exe`）は **uiAccess=true** で動くので、キーフックにキーが届き、
  `SendInput` も届きます（UIPI を越える）。次のときは、届きません: (1) uiAccess が効いていない（uiAccess の無い版 `tray\kasane-tray-nua.exe` を使っている、開発ビルドなど）。
  (2) UAC の確認画面などのセキュアデスクトップ（uiAccess でも届かない）。(3) トレイを、エクスプローラー（ログオン時の自動起動、スタートメニュー、ダブルクリック）以外の
  プログラム（`Start-Process`、コマンドプロンプトなど）から起動した場合: **エラーは出ませんが、uiAccess なしで動きます**。uiAccess を効かせるには、エクスプローラーから起動する
  か、ログオンし直してください。効いているかは、Process Explorer の「UIAccess」の列（View → Select Columns → Process Security）で確かめられます。
  なお、`Launch` で起動したアプリには uiAccess は引き継がれません。
- **トレイが起動しないとき**: uiAccess=true のトレイは、署名が信頼されない、または `Program Files` の外にあると、エクスプローラー（ログオン時の自動起動など）から
  起動したときに、失敗して何も出ません（署名済みのインストーラーで入れたときは起こりません）。エクスプローラー以外（`Start-Process` など）から起動すると、失敗せずに
  uiAccess なしで動きます。その場合は、同じフォルダの `kasane-tray-nua.exe`（uiAccess の無い版。管理者ウィンドウの前面では
  キーフック・`SendInput` が届かない）を起動してください。ログイン時の自動起動は、`tray\kasane-tray.exe` を指します。
- **ロック画面・ユーザーの切り替え・別のセッションがアクティブなとき**は、動作を実行しません。ロックの検知は、切り替えのあと最大 2 秒ほど遅れることがあり、
  その間に押した動作が 1 回実行されることがあります。
- **一時停止中**は、`PauseToggle` だけが動きます（ホットキーで再開できるように）。
- マウスの相対移動（`move`）は、Windows のポインター加速を受けます。位置を決めたいときは `moveto` を使います。
- 5 秒より前の `HLP(Id)` の押下は捨てます（トレイが止まっていた間のキーが、あとでまとめて動かないように）。実行待ちは 64 件までで、あふれた押下は捨てます。

## 困ったとき

- 動かない: ① トレイが動いているか（通知領域のアイコン）、② `HLP(Id)` の `Id` が `Actions` にあるか（キー割り当て画面が注意を出します）、③ 適用したか、
  ④ `%LOCALAPPDATA%\applet\kasane\tray.log` に、helper.json の読み込みの失敗や、`Session: active=…` の切り替わりが出ていないか。
- `tray.log` の `Session:` の行は、動かしてよいか（アクティブなセッションで、ロックされていない）が変わるたびに 1 行出ます。どの信号（`wtsLocked` / `desktopDenied` / `lockApp`）で止まったかが分かります。
- 電源キー（`KC_PWR`・`KC_SLEP`・`KC_WAKE`）を割り当てるときは確認が出ます（PC がスリープ・シャットダウンすることがあるため）。

のどかの設定から変換して取り込むには [IMPORT-NODOKA.md](IMPORT-NODOKA.md)、設定のエクスポート／インポートは [TUTORIAL-GUI.md](TUTORIAL-GUI.md)、仕組みは [ARCHITECTURE.md](ARCHITECTURE.md) を見てください。
