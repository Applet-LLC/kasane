# ヘルパー動作とアプリ別レイヤー

タスクトレイの kasane（`kasane-tray.exe`）が、キーで「キーボードの外」の動作を動かします。

- ヘルパー動作: キーで、プログラムの起動・URL やファイルを開く・文字列の入力（日本語も可）・キーの列・マウス操作・レイヤーの操作・一時停止の切り替えを行います。
- アプリ別レイヤー: 前面のアプリに応じて、レイヤーを立てる、またはそのキーボードのリマップを OFF にします（ゲームなど）。

ヘルパー動作とアプリ別レイヤーの設定は、管理者権限なしで保存できます。設定は利用者のフォルダに保存され、設定画面の **OK** で保存すると、トレイが数秒で読み直します。
ただし、キーに `HLP(Id)` を割り当てて動かすには、ほかのキー割り当てと同じく **キーボードに適用**（管理者権限が要ります）が必要です。トリガーとアプリ別レイヤーは適用が要りません。
トレイが動いている必要があります（トレイが止まっていると、`HLP(id)` のキーは何も出さず、トリガーのキーは普通のキーとして通ります）。

## すぐ試す

1. メイン画面でキーを選び、**キー割り当て** 画面の **ヘルパー動作** カテゴリを開きます。**新しい動作...** で動作を作ると、そのキーに `HLP(Id)` が入ります。
2. **キーボードに適用** します（`HLP(Id)` はレイヤーマップの一部なので、適用が要ります）。
3. そのキーを押すと、キー自体は何も出さず、トレイが動作を実行します。

F13〜F24 などのキーで動かしたいときは、**設定...** の **ヘルパー動作** タブの **トリガー** に作ります（適用は要りません）。

## 保存先

| 範囲 | 場所 | 使う場面 |
|---|---|---|
| このキーボード | `%LOCALAPPDATA%\applet\kasane\<UniqId>\helper.json` | そのキーボードだけで動かす |
| 全キーボード共通 | `%LOCALAPPDATA%\applet\kasane\tray.json` の `Helper` | どのキーボードでも動かす |

動作を引くときは、キーボードごとの設定 → 共通の設定の順に探します。helper.json は手で書いてもかまいません（`samples/helper.sample.json` に例があります）。
構文を間違えると、そのファイルは読まれません（設定画面は、壊れたファイルを黙って上書きせず、理由を出します。トレイは無視して `tray.log` に残します）。

## 動作の種類

動作は `Actions`（`HLP(Id)` から呼ぶ。`Id` は 0〜65535。新しい動作には 1 から振ります）と `Triggers`（キーで動かす）に、同じ形で書きます。

| Type | 内容 | 主な項目 |
|---|---|---|
| `Launch` | プログラムを起動する（昇格はしない） | `Path`、`Args`、`WorkDir`（省略するとトレイの作業フォルダ） |
| `Open` | URL・ファイル・フォルダを、関連付けられたアプリで開く | `Path` |
| `Sequence` | 手順を順に実行する（キー・文字列・待ち・マウス・ホイール） | `Steps`、`ReleaseSteps`（キーを離したとき）、`Repeat`、`KeepMods`（トリガーのみ） |
| `Text` | 設定した文字列を、そのまま入力する（`Apple 漢字` など。いま入力できる場所の現在の位置に追記される。改行は Enter、タブは Tab。`Sequence` の `text` と違い、バックスラッシュに特別な意味は無い。最大 900 文字） | `Text` |
| `AppLayer` | アプリ管理レイヤーを操作する | `Layers`（0〜15）、`LayerOp`（`On` / `Off` / `Toggle` / `Hold`。`Hold` は押している間だけ） |
| `PauseToggle` | トレイの一時停止・再開を切り替える | なし |
| `KillLine` | Emacs の C-k。行末まで切り取り、続けた分をクリップボードに連結する | なし |

`Repeat` が true のときだけ、キーのオートリピートで繰り返し実行します。

`KeepMods` は、**トリガー**（キー＋修飾キー）で動かす `Sequence` と `Text` だけに効きます。既定（false）では、実行の間だけ、トリガーの修飾キーのうち物理的に押している分を OS から隠します（`SendInput` で離したことにし、終わったときにまだ押していれば戻します）。Ctrl+F1 で文字列を出すとき、出力に Ctrl が掛からないようにするためです。true にすると、押している修飾キーを隠さずに実行します。`HLP(id)` のキーには関係しません。

### 行末までの切り取り（`KillLine`、Emacs の C-k）
`Shift+End`、`Ctrl+X` を送って行末までを切り取り、クリップボードに連結して書き戻します（のどかの `&EmacsEditKillLine` と同じ）。C-k を続けて押すと、切り取った分が 1 つにつながり、C-y（貼り付け）で戻せます。
- 行末で押したときは、改行をつないで `Delete` を送ります（次の行が上がってきます）。
- 切り取りで改行まで取れるアプリ（ブラウザのテキスト欄など）では、改行をつなぎに入れず、`Enter`、`←` で戻します。
- つなぎをやめるのは、C-k 以外のキーを押したとき、前面のウィンドウが変わったとき、クリップボードに別の内容が入ったとき、60 秒たったときです。
- 押している Ctrl は、実行の間だけ OS から隠します（隠さないと、`Ctrl+Shift+End` で文書の終わりまで選ばれます）。
- キーには、キー置換の置き換え先に `HLP(Id)` を置いて割り当てます（Ctrl+K → `HLP(Id)`）。**キーボードに適用** が要ります。設定は要りません。
- 最初に使ったときから、トレイが、実際のキー入力を見張るフックを張ります（C-k 以外のキーを知るため）。キーの内容は記録しません。

### 一時停止・再開をキーで行う（`PauseToggle`）
トレイのメニューの「一時停止」と同じ動作を、キー 1 つで行えます。機能の追加は要らず、`PauseToggle` の動作を作って、キーに割り当てるだけです。
1. **設定...** の **ヘルパー動作** タブで、動作の種類を「一時停止・再開 (PauseToggle)」にして作ります。
2. キーに結び付けます。次のどちらかです。
   - `HLP(Id)` で動かす場合: キー割り当て画面の **ヘルパー動作** から、作った動作をキーに置きます。**キーボードに適用** が要ります。ただし、一時停止中はキーボードのリマップが止まるので、
     `HLP` のキーは届きません（止めることはできても、同じキーで再開はできません）。
   - トリガー（F13〜F24 など）で動かす場合: **トリガー** に、キー（例: `KC_F13`、修飾キーは `Shift` / `Ctrl` の組み合わせがおすすめ）で結び付けます。トリガーは一時停止中も動くので、
     同じキーで再開できます。F13〜F24 の物理キーが無く、別のキーを `KC_F13` に割り当てて出す場合は、一時停止中にそのキーのリマップが止まって F13 を出せないので、
     同じキーでは再開できません（物理の F13〜F24 キーを使うか、メニューの「一時停止」で再開してください）。
3. 一時停止中は、`PauseToggle` だけが動きます（ほかの動作は止まります）。

### 手順（Sequence）の書き方

設定画面では、1 行 1 手順のテキストで書きます（`#` から始まる行は無視）。

書くのが大変なものは、欄の上のボタンで挿入できます（カーソルのある行の次に、1 行入ります）:

- **キーを押して挿入**: 命令（`key`／`down`／`up`）を選び、このボタンを押してから入れたいキーを押すと、`key KC_A` のような行が入ります（Esc で取消）。Win キーや Alt+Tab は取れないので、次のボタンを使います。
- **選んで挿入...**: 画面のキーボードや一覧からキーを選びます（`LCTL(KC_C)` のような修飾つきも選べます）。
- **マウス操作を挿入 ▾**: メニューから、ボタンのクリック・押す・離す、移動、ホイールの定型の行を選びます（`mouse left`、`mouse left down`、`move 10 0`、`wheel 120` など。数値は、挿入後に書き換えます）。
- **IME 操作を挿入 ▾**: メニューから、IME を ON・OFF・切り替える行を選びます（`ime on`、`ime off`、`ime toggle`）。方式を固定した行（`ime off key` など）も選べます。
- **仮想キーを挿入 ▾**: メニューから、日本語 IME 向けの仮想キーの行を選びます（`vk IME_ON`、`vk IME_OFF`、`vk KANJI`、`vk CONVERT`、`vk NONCONVERT` など）。

```
key LCTL(KC_C)       キーを押して離す（KC_A、LCTL(KC_C)、SC_E06A など）
down KC_A / up KC_A  押す / 離す
vk IME_ON            仮想キー（VK_*）を押して離す（IME_ON、0x16、LSHIFT+F1 など。vkdown / vkup は押す / 離す）
text こんにちは\n     文字列を打つ（\n = Enter、\t = Tab、\\ = バックスラッシュ）
delay 50             待つ（ミリ秒、0〜10000）
mouse left           ボタンをクリック（left right middle x1 x2。mouse left down / up も）
move 10 -5           マウスを今の位置から動かす
moveto 100 200       マウスを画面（仮想デスクトップ）の座標へ動かす
wheel -120           縦ホイール（120 で 1 ノッチ）
hwheel 120           横ホイール
ime off              IME を OFF にする（on / off / toggle。今の状態を見て、違うときだけ変える）
ime off abort        切り替えに失敗したら、この動作の残りをやめる（書かなければ続ける）
ime on imm           方式を固定する（imm / tsf / key / altkanji。以前の設定との互換。GUI では選べない）
```

#### IME の ON/OFF（`ime`）

日本語の IME が ON のとき、`key` で送るキーは、かな入力や変換の対象になります。手順の途中で IME を OFF にしたいときは、`ime off` を書きます。
今の IME の状態を読み、目標と同じなら何もしません。違うときだけ変えます。欄の上の **IME 操作を挿入 ▾** から、行を挿入できます。
状態の読み方は、`tray.json` の `ImeSource`（設定の **IME の状態の取得方法**。IME 連動と同じ）に従います。TSF を含む方法を選ぶと、IME 連動を使っていなくても、天狼のフックを入れます。

方式を書かない行（ふつうの書き方）の切り替え方は、`tray.json` の `ImeSwitch`（設定の **IME の切り替え方**）で決まります（2026-11-05。`ImeRoutePlanner`）。

| `ImeSwitch` | 試す順 |
|---|---|
| `Auto`（既定。項目が無いときも） | 通常の権限のトレイ: IMM32 → IME キー（`VK_IME_ON` / `VK_IME_OFF`）。管理者として動くトレイ: ドライバ経由の Alt+半角/全角 → IMM32 → IME キー。ドライバ経由は、送れそうなとき（1.01 以降のドライバ、ライセンスが有効、直近 60 秒に失敗していない）で、今の状態を読めたときだけ。送れなければ `SendInput` には戻さず、IMM32 へ進む |
| `ImeKeys` | IME オン / IME オフ キー → IMM32。管理者として動くトレイはドライバ経由でスキャンコード E0 F2 / E0 F1（USB の LANG1 / LANG2。日本語キーボードの配列で `VK_IME_ON` / `VK_IME_OFF` になる）、送れなければ `SendInput` で `VK_IME_ON` / `VK_IME_OFF` |
| `Henkan` | 変換（0x79）/ 無変換（0x7B） → IMM32。Microsoft IME で、変換に IME-オン、無変換に IME-オフを割り当てておく前提。送り方は `ImeKeys` と同じ（`SendInput` では VK_CONVERT / VK_NONCONVERT） |
| `Toggle` | Alt+半角/全角 → IMM32。今の状態を読めないときは IMM32 だけ。ドライバ経由で送れなければ `SendInput` |
| `Imm` | IMM32 だけ |

IME オン / オフ キーと変換 / 無変換は、ON/OFF を直接指定するキーなので、今の状態を読めなくても送ります（読めず、反映を確かめられないときは、送ったことで成功とする）。
Microsoft IME に割り当てが無いと、変換は再変換として働き、入力済みの文字を変換中の文字に取り込みます（2026-11-05 の試験。Text の「元に戻す」で、窓の文字列が消えて以降のキーが `E5` になった）。そのため、変換 / 無変換を送って、状態を読めたのに変わらなかったときは、割り当てが無いとみなし、`ImeSwitch` が変わるかトレイを起動し直すまで、変換 / 無変換を送りません（IMM32 だけで変える）。最初の操作が `ime on` のときは見分けられないので、この危険は残ります。
Alt+半角/全角は切り替えのキーなので、送ったのに反映されないときも送り直しません（遅れて反映されると二重に切り替わる）。次の IMM32 は ON/OFF を直接指定するので、続けても二重にはなりません。
ドライバ経由で送ったキーには、注入の印（`LLKHF_INJECTED`）が付きません。トレイは、送る直前から 300 ms、そのキーをトリガーとして拾いません（無変換をトリガーにしていても、送った無変換で動作が再び起きないように）。

ドライバ経由で E0 F2 / E0 F1 を送って IME が切り替わるかは、実機で未確認です（配列の表には VK→スキャンコードの対応があるが、`MapVirtualKeyEx` の逆向きは 0 を返した）。キーマップの `KC_LNG1` / `KC_LNG2` も同じスキャンコードを出力します。
切り替えたときは、使った方法を `tray.log` に 1 行残します（例: `IME: ドライバ経由の Alt+半角/全角で OFF にしました`）。トレイの起動時には、トレイが管理者として動いているかも 1 行残します。

IME が切り替わらないアプリでは、`ime` の代わりに `vk IME_ON` / `vk IME_OFF` を試してください（次の節）。

方式を書いた行（`ime on imm`、`ime off key`、`ime off altkanji`、`ime on tsf`）は、1.00 からの設定との互換のために残しています。GUI のメニューと、Text の方式の欄からは外しました（Text の欄は、方式を書いた設定を開いたときだけ出ます）。

| 方式 | 内容 |
|---|---|
| `imm` | IMM32 だけ。IME のウィンドウに ON/OFF を設定させる |
| `key` | IME キー（`VK_IME_ON`、`VK_IME_OFF`）だけ。状態を読めなくても送る |
| `altkanji` | Alt+半角/全角だけ。切り替え動作なので、今の状態を読めないときは送らない。ドライバ経由で送れればドライバ経由、送れなければ `SendInput` |
| `tsf` | TSF だけ（実験的）。効くかどうかは IME とアプリ次第で、試験ではほとんど効かなかった |

方式を書いたときは固定で、失敗しても別の方式に切り替えません。どの書き方でも、失敗したときは記録して続けます（`abort` を付けると、その動作の残りをやめます）。

#### 仮想キー（`vk`）

`key` はスキャンコードで送るので、スキャンコードを持たないキーは送れません。Microsoft の日本語キーボード向けの IME ON/OFF キー（`VK_IME_ON`、`VK_IME_OFF`）がそうです。こうしたキーは `vk` で、仮想キーコードのまま送ります。

```
vk IME_ON            IME を ON にするキー（IME が OFF のときも ON のときも、ON にする）
vk IME_OFF           IME を OFF にするキー
vk KANJI             半角/全角（切り替えのキー。今の状態は見ない）
vk 0x70              数値でも書ける（0x16 か 10 進。1〜254）
vk LSHIFT+F1         + でつないだ左の分は修飾キー（LSHIFT RSHIFT LCTRL RCTRL LALT RALT LWIN RWIN。SHIFT CTRL ALT WIN は左の別名）
vkdown LCTRL         押す。vkup LCTRL は離す
```

名前は `VK_` を付けても付けなくてもかまいません。日本語 IME 向けには `IME_ON`、`IME_OFF`、`KANJI`、`KANA`、`CONVERT`、`NONCONVERT`、`ACCEPT`、`MODECHANGE`、`DBE_HIRAGANA`、`DBE_KATAKANA`、`DBE_ALPHANUMERIC` などが使えます。
そのほかに、文字キー（`A`〜`Z`）、`F1`〜`F24`、テンキー（`NUMPAD0`〜`NUMPAD9`、`ADD`、`SUBTRACT`、`MULTIPLY`、`DIVIDE`、`DECIMAL`）、`NUMLOCK`、`SCROLL`、`CAPITAL`（CapsLock）、`PAUSE`、`SNAPSHOT`（PrintScreen）、矢印や編集のキー（`LEFT`、`HOME`、`DELETE` など）、記号キー（`OEM_1`〜`OEM_8`、`OEM_PLUS`、`OEM_COMMA`、`OEM_MINUS`、`OEM_PERIOD`、`OEM_102`）、音量・メディア・ブラウザのキー（`VOLUME_UP`、`MEDIA_PLAY_PAUSE`、`BROWSER_BACK` など）が使えます。
数字キー（`0`〜`9`）は、`VK_0`〜`VK_9` と書きます（`vk VK_4`、`vk LSHIFT+VK_1`）。`VK_` を付けない `4` は数値（VK コード）として読むので、数字キーの意味にはなりません。`vk 0x34` のように数値でも書けます。`NUMPAD4` と `LEFT` は別のキーです（テンキーの 4 を、NumLock の状態に関わらず送ります）。
`vk` は、`ime` と違って今の IME の状態を読みません。送ったキーに IME が応えるかどうかは、IME とアプリによります。`vk` は常に `SendInput` で送ります（ドライバは使いません）。

通常のウィンドウでは、`vk IME_ON`、`vk IME_OFF`、`vk KANJI`、`vk LSHIFT+0x41` が期待どおりに働くことを確かめています（2026-10-31）。

#### IME の ON/OFF の制限事項

IME の ON/OFF は、効かないことがあります（2026-10-31 の実機試験。Microsoft IME。`.plans/handoff/ime-control-results.md`）。

- アプリによっては切り替えられません。IME のウィンドウを持たない・応答しないアプリには、IMM32 の操作が届きません。失敗の理由は `tray.log` の `IME(...)` の行に残ります。方式を書かない行は、IMM32 で変えられなければ IME キーを送ります。方式を固定した行は、切り替えません。
- `tsf` は、ほとんど効きません（実験的）。テスト用のウィンドウでは効かず、メモ帳（新）では効いたように見えましたが、IME の読み取りが不安定で、確かではありません。
- 管理者として動くウィンドウでは、IME は IMM32 で切り替わります。`key`・`vk`・`Text` は、一部が届かないことがあります。届くかどうかは、キーの種類と並びで変わります（`key A` の次に `key F24` を置くと F24 だけ届き、`key F24` の次に `key A` を置くと、どちらも届きませんでした）。通常のウィンドウでは、すべて届きます。uiAccess の無い版では、IME の切り替えも届きません。
- 昇格したトレイでドライバ経由の Alt+半角/全角を送ると、管理者のウィンドウでも IME が切り替わりました（IME ON/OFF の 20 回、`ime off altkanji` + `key A` の 10 回とも期待どおり。2026-11-02 の実機試験。当時は `altkanji` を書いた行で試した。今は、管理者として動くトレイの既定がこの経路）。このとき、先頭のドライバ経由のキーの後ろでは `SendInput` の `key A` も届きました（8/8）。ドライバを通らない `ime off imm` + `key A` や、IME が OFF のままでキーを送らなかった場合は、0〜1/8 でした。原因は調べていません。管理者保護を有効にした環境では、未確認です。
- IME の状態を読み取れないアプリでは、Text の「元に戻す」を確かめられません。
- Microsoft IME 以外（Google 日本語入力など）と、ARM64 は、試験していません。

`Text`（文字列を入力する）には、**入力の間だけ IME を OFF にして、終わったら元に戻す** という選択があります（`helper.json` では `ImeOffDuring`、`ImeMethod`、`ImeOnFail`）。
文字列は Unicode のまま送るので、通常は IME の状態に左右されません。それでも崩れるアプリがあるときに使います。

`helper.json` では、同じ内容を `Steps` の配列（`{ "Key": "LCTL(KC_C)" }`、`{ "DelayMs": 50 }`、`{ "Text": "こんにちは\n" }`、
`{ "Mouse": "Left", "MouseAction": "Down" }`、`{ "MoveX": 10, "MoveY": -5 }`、`{ "Wheel": -120 }` など）で書きます。
手順は最大 2000 件、待ちは 1 回 10 秒・1 動作の合計 60 秒までです。

マウスのボタンを「押している間だけ押す」（ドラッグ）には、`Steps` に `mouse left down`、`ReleaseSteps` に `mouse left up` を書きます。

## トリガー（F13〜F24 などのキー）

`Triggers` は、キー（`Key`）と修飾キー（`Mods`。`MOD_LSFT|MOD_LCTL` のように。左右は区別しません）に動作を結び付けます。

- 1 つでもあると、トレイはキーボードフック（低レベルフック）を張ります。`HLP(Id)` だけの設定ではフックは張られません。
- 一致したキーは、アプリに届かなくなります（押下・リピート・解放を飲み込みます）。修飾キーは、押している分と過不足なく一致したときだけです。
- キーボードごとの設定が先、共通が後です。キーボードは、ドライバが入力に刻む識別子（`dwExtraInfo` の上位 16bit）で見分けます。
- F13〜F24 は、キー割り当てで出せます（物理キーが無くても、キーを `KC_F13` に割り当てれば出ます）。
- `Sequence` の修飾キーの扱いは、上の `KeepMods` を見てください（既定では、実行の間だけ隠します）。
- Alt や Win を使うと、単独で離したときにメニューやスタートが開くことがあります。`Sequence` で修飾キーを隠す・戻すときは、間に F24 のキーを入れて防ぎます。それ以外の動作（`Launch` など）では、Shift / Ctrl の組み合わせがおすすめです。
- Win を含むトリガーで F16 を選ぶと、環境によっては、スライドしてシャットダウンの画面が出ることがあります（トリガーなしで Win+F16 を押しても出るので、Windows 側のホットキーとみられます）。Win を使うときは、F13〜F15・F17〜F24 のように、別のキーを選んでください。
- F24 は内部でも使います。トリガーの修飾キーに Alt または Win を含む `Sequence` は、実行の前（修飾キーを隠すとき）と後（戻すとき）に、F24 を1回ずつ押して離す入力（`SendInput`、スキャンコード `0x76`）を送ります。F24 にショートカットを割り当てたアプリやツールがあると、それが動いてしまいます。Ctrl・Shift だけのトリガーでは使いません。F24 を使いたいときは、トリガーに Alt・Win を含めないか、`KeepMods` を true にします（修飾キーを隠さないので、F24 も送りません）。トレイのキーフックは、注入された入力を見ないので、この F24 でトリガーが動くことはありません。

## NICOLA の IME 連動のキーボードごとの設定（`NicolaImeLink`）

NICOLA の IME 連動（IME がかなモードのときだけ NICOLA のレイヤーを立てる）は、全キーボード共通の `tray.json` の `ImeLink`（既定はオフ）で決めます。
キーボードごとに変えたいときは、そのキーボードの `helper.json` の `"NicolaImeLink": true`（連動する）または `false`（連動しない）を書きます。
キーボードごとの設定が先で、無ければ（`null`）共通に従います。設定画面の **IME連動** タブの NICOLA の部分で、「対象」を選んで設定できます。

## IME連動のレイヤー（`ImeLayers`）

IME の ON/OFF に合わせて、アプリ管理レイヤーを立てる・下ろします。NICOLA（`ImeLink`）とは別の機能で、NICOLA を使わなくても使えます。
設定画面の **IME連動** タブから設定します。

```json
"ImeLayers": { "Enabled": true, "Layers": [1], "Mode": "On" }
```

| 項目 | 内容 |
|---|---|
| `Enabled` | 連動するか（既定は true）。キーボードごとの設定で false にすると、共通の設定があっても、そのキーボードは連動しません |
| `Layers` | 立てるレイヤー（0〜15）。1つ以上 |
| `Mode` | `On`（IME が ON のとき。既定。IMM32 で読んだ IME の ON/OFF のとおり。Microsoft IME では、半角英数のモードは OFF（`Open=False`）として読めるので、OFF と同じ扱いになる。IME によっては、半角英数でも ON のことがある）／`Kana`（かな入力のときだけ。IME が ON で、日本語の入力モード） |

- キーボードごとの設定（`helper.json`）が先、無ければ共通（`tray.json` の `Helper`）を使います。
- 立てるレイヤーは、IME 連動（NICOLA）・前面のアプリの規則と同じアプリ管理レイヤーで、キーボード側の `TG` などとは OR で重なります。
- 前面のウィンドウの IME の状態が取れないとき（管理者として動いているウィンドウ、応答しないアプリなど）は、直前の状態を保ちます。
- IME の状態は、IMM32（`WM_IME_CONTROL` の `IMC_GETOPENSTATUS`・`IMC_GETCONVERSIONMODE`）で読み、取れないときは Text Services Framework（TSF）で補います（設定の「IME連動」タブの「IME の状態の取得方法」。既定は「IMM32 のみ」。TSF は実験的で、Explorer を開くのが遅く感じられる場合があります。
  「IMM32 のみ」を選ぶと、TSF 用の DLL（天狼の sirius_hook）を入れません）。TSF の値は、別プロセスのトレイからは読めない（空。2026-10-18 の測定）ので、全アプリに入る小さな DLL が、アプリの中で読んだ値を使います。32bit のアプリ・ARM64 ネイティブのアプリには、この DLL は入りません。
  IMM32 で状態が取れない、または追従しないアプリ: 管理者として動くウィンドウ（UIPI）、設定アプリなど一部のストアアプリ（値が固定）。新しいメモ帳でも、ON が読めないことがありました。
  そのようなアプリが前面のとき、直前の状態を保ちます。
- NICOLA の連動と、同じレイヤーを指していても構いません（どちらかが立てたいときに立てます）。

## アプリ別レイヤー

`AppLayerRules` に規則を並べます。上から順に見て、最初に一致した規則を使います。どれにも一致しなければ、`Default` の規則（無ければ何もしません）。
キーボードごとの規則 → 共通の規則の順です。

| 項目 | 内容 |
|---|---|
| `Match.Exe` | exe のファイル名（`code.exe`）。`\` を含めばフルパスで比べる |
| `Match.PathRegex` / `Match.TitleRegex` | exe のフルパス / ウィンドウのタイトルの正規表現（部分一致） |
| `Match.Class` | トップレベルのウィンドウのクラス名 |
| `Match.NodokaClass` / `Match.NodokaTitle` / `Match.NodokaOr` | のどかの `window` と同じ照合（`exeのフルパス:クラス:…:フォーカスのクラス`） |
| `Layers` | 立てるレイヤー（0〜15）。IME 連動など、ほかの入力源のレイヤーとは別に重なります |
| `MapOff` | そのアプリが前面の間、そのキーボードのリマップを OFF（素通し）にする |
| `Default` / `Enabled` / `Name` | どれにも一致しないときの規則 / 有効 / 表示名 |

指定した項目はすべて一致したときに一致します。条件を 1 つも指定していない規則は、照合に使いません。設定画面の **実行中のアプリから選ぶ** で、今開いているウィンドウから
exe とクラスを入れられます。`MapOff` は、一時停止中は触りません。トレイが落ちても、`MapOff` で OFF にしたキーボードは次の起動で ON に戻します。

## 動く条件と制約

- 管理者として動くウィンドウが前面のとき: インストールしたトレイ（`tray\kasane-tray.exe`）は uiAccess=true で動くので、キーフックにキーが届き、
  `SendInput` も届きます（UIPI を越える）。次のときは、届きません: (1) uiAccess が効いていない（uiAccess の無い版 `tray\kasane-tray-nua.exe` を使っている、開発ビルドなど）。
  (2) UAC の確認画面などのセキュアデスクトップ（uiAccess でも届かない）。(3) トレイを、エクスプローラー（ログオン時の自動起動、スタートメニュー、ダブルクリック）以外の
  プログラム（`Start-Process`、コマンドプロンプトなど）から起動した場合: エラーは出ませんが、uiAccess なしで動きます。uiAccess を効かせるには、エクスプローラーから起動する
  か、ログオンし直してください。効いているかは、Process Explorer の「UIAccess」の列（View → Select Columns → Process Security）で確かめられます。
  管理者保護を使っているときは、インストーラーが作るタスク（`startproc.exe` 経由）で起動しても、uiAccess が付くことを確認しています（`tray.log` の最初の行の `uiAccess=あり`）。
  なお、`Launch` で起動したアプリには uiAccess は引き継がれません。
- トレイが起動しないとき: uiAccess=true のトレイは、署名が信頼されない、または `Program Files` の外にあると、エクスプローラー（ログオン時の自動起動など）から
  起動したときに、失敗して何も出ません（署名済みのインストーラーで入れたときは起こりません）。エクスプローラー以外（`Start-Process` など）から起動すると、失敗せずに
  uiAccess なしで動きます。その場合は、同じフォルダの `kasane-tray-nua.exe`（uiAccess の無い版。管理者ウィンドウの前面では
  キーフック・`SendInput` が届かない）を起動してください。ログイン時の自動起動は、`tray\kasane-tray.exe` を指します。
- ロック画面・ユーザーの切り替え・リモートデスクトップの切断・別のセッションがアクティブなときは、動作を実行しません。リモートデスクトップで接続している間（ロックされていないとき）は、実機のコンソールと同じように動きます。ロックの検知は、切り替えのあと最大 2 秒ほど遅れることがあり、
  その間に押した動作が 1 回実行されることがあります。
- 一時停止中は、`PauseToggle` だけが動きます（ホットキーで再開できるように）。
- マウスの相対移動（`move`）は、Windows のポインター加速を受けます。位置を決めたいときは `moveto` を使います。
- 5 秒より前の `HLP(Id)` の押下は捨てます（トレイが止まっていた間のキーが、あとでまとめて動かないように）。実行待ちは 64 件までで、あふれた押下は捨てます。

## 困ったとき

- 動かない: ① トレイが動いているか（通知領域のアイコン）、② `HLP(Id)` の `Id` が `Actions` にあるか（キー割り当て画面が注意を出します）、③ 適用したか、
  ④ `%LOCALAPPDATA%\applet\kasane\tray.log` に、helper.json の読み込みの失敗や、`Session: active=…` の切り替わりが出ていないか。
- `tray.log` の `Session:` の行は、動かしてよいか（アクティブなセッションで、ロックされていない）が変わるたびに 1 行出ます。どの信号（`wtsLocked` / `desktopDenied` / `lockApp`）で止まったかが分かります。
- 電源キー（`KC_PWR`・`KC_SLEP`・`KC_WAKE`）を割り当てるときは確認が出ます（PC がスリープ・シャットダウンすることがあるため）。

のどかの設定から変換して取り込むには [IMPORT-NODOKA.md](IMPORT-NODOKA.md)、設定のエクスポート／インポートは [TUTORIAL-GUI.md](TUTORIAL-GUI.md)、仕組みは [ARCHITECTURE.md](ARCHITECTURE.md) を見てください。
